# 计算机网络 第六章 网络应用相关协议与模型

## 6.1 网络应用模型

### 客户/服务器(C/S)模型

#### 概述

- 在客户/服务器(C/S)模型中，有一个总是打开的主机称为**服务器**，它服务于许多来自其他称为**客户机**的主机请求，服务器处于接收请求的状态。
- 客户机是**服务请求方**，服务器是**服务提供方**。

#### 工作流程

1. 客户机发出服务请求，并等待接收结果；
2. 服务器收到请求后，分析请求，进行必要的处理，得到结果并发送给客户机。

#### 主要特征

- 网络中各计算机的地位**不平等**：服务器可通过对用户权限的限制管理客户机，阻止客户机随意存储/删除数据或进行其他受限网络活动；
- 客户机相互之间**不直接通信**；
- 可扩展性**不佳**。

#### 应用场景

- Web、文件传输协议(FTP)、远程登录、电子邮件。

### P2P模型

#### 概述

- 网络中各计算机**没有固定的客户和服务器划分**；
- 任意一对计算机称为**对等方(Peer)**，可直接相互通信；
- 每个结点既作为客户访问其他结点的资源，也作为服务器提供资源给其他结点访问。

#### 应用场景

- PPlive、Bittorrent、电驴。

#### 优点

- 减轻了服务器的计算压力，消除了对某个服务器的完全依赖，提高了系统效率和资源利用率；
- 多个客户机之间可以直接共享文档；
- 可扩展性好：传统服务器受响应和带宽限制，只能接受一定数量的请求，P2P模型无此限制。

#### 缺点

- 各大互联网服务提供商（如电信、网通等）通常对P2P应用持反对态度；
- 易使网络变得非常拥塞。

## 6.2 域名系统(DNS)

### 基本概述

- 域名系统(DNS)是因特网使用的命名系统，用于将便于人们记忆的**主机名**（如www.cskaoyan.com）转换为便于机器处理的**IP地址**；
- DNS系统采用**客户/服务器模型**，协议运行在UDP之上，使用**53号端口**；
- 因特网采用**层次树状结构**的命名方法，任何连接到因特网的主机或路由器，都有一个唯一的层次结构名称（即域名）。

### 层次域名空间

#### 域名规则

- 标号中的英文**不区分大小写**；
- 标号中除连字符(-)外，不能使用其他标点符号；
- 每个标号不超过63个字符，多标号组成的完整域名最长不超过255个字符；
- 级别最低的域名写在**最左边**，级别最高的顶级域名写在**最右边**。

#### 顶级域名分类

1. **国家顶级域名(nTLD)**：代表国家和某些地区，如“cn”（中国）、“us”（美国）、“uk”（英国）；
2. **通用顶级域名(gTLD)**：常见包括“com”（公司）、“net”（网络服务机构）、“org”（非营利性组织）、“gov”（国家或政府部门）等；
3. **基础结构域名**：仅一个“arpa”，用于反向域名解析，又称反向域名。

### 域名服务器分类

因特网的域名系统是联机分布式数据库系统，采用客户/服务器模型，域名服务器分为以下四类：

1. **根域名服务器**：最高层次的域名服务器，所有根域名服务器均知道所有顶级域名服务器的IP地址；
2. **顶级域名服务器**：负责管理在该服务器注册的所有二级域名，收到DNS查询请求时，返回对应的回答（可能是最终结果，也可能是下一应查找的域名服务器IP地址）；
3. **授权域名服务器（权限域名服务器）**：总能将其管辖的主机名转换为该主机的IP地址，每台主机都必须在授权域名服务器处登记；
4. **本地域名服务器**：当主机发出DNS查询请求时，请求报文会发送给该主机的本地域名服务器；每个因特网服务提供者(ISP)、大学甚至大学中的各个系，都可拥有本地域名服务器。

### 查询方式

#### 解析类型

- **正向解析**：将域名映射为IP地址；
- **反向解析**：将IP地址映射为域名。

#### 查询模式

- **递归查询**：客户机向本地域名服务器发出DNS请求报文，若本地服务器无记录，会代替客户机向其他服务器查询，最终将结果返回给客户机；该方式会给根域名服务器造成过大负载，实际中几乎不使用；
- **递归与迭代相结合的查询**：主机向本地域名服务器的查询采用**递归查询**，本地域名服务器向根域名服务器的查询采用**迭代查询**（根服务器返回下一级服务器地址，本地服务器自行向下查询）。

### 域名解析过程

1. 本地域名服务器收到请求后，先查询本地缓存，若无该记录，则以DNS客户的身份向根域名服务器发出解析请求；
2. 根域名服务器收到请求后，判断该域名所属域，将对应的顶级域名服务器（如dns.com）的IP地址返回给本地域名服务器；
3. 本地域名服务器向顶级域名服务器（如dns.com）发出解析请求报文；
4. 顶级域名服务器（如dns.com）收到请求后，判断该域名属于下级域（如abc.com域），将对应的授权域名服务器（如dns.abc.com）的IP地址返回给本地域名服务器；
5. 本地域名服务器向授权域名服务器（如dns.abc.com）发起解析请求报文；
6. 授权域名服务器（如dns.abc.com）收到请求后，将查询结果返回给本地域名服务器；
7. 本地域名服务器将查询结果保存到本地缓存，同时返回给客户机。

### 高速缓存

#### 优点

- 提高DNS的查询效率；
- 减少因特网上的DNS查询报文数量。

#### 注意事项

主机名和IP地址之间的映射**不是永久的**，因此DNS服务器会在一段时间后丢弃高速缓存中的信息。

## 6.3 文件传输协议(FTP)

### FTP功能

- 提供交互式访问，允许客户指明文件的类型与格式，并允许文件具有存取权限；
- 采用**客户/服务器**的工作方式，使用TCP可靠的传输服务；
- 屏蔽各计算机系统的细节，适合在异构网络中的任意计算机之间传送文件；
- 以用户权限管理的方式，提供用户对远程FTP服务器上文件的管理能力；
- 提供不同种类主机系统（硬、软件体系不同）之间的文件传输能力；
- 以**匿名FTP**的方式提供公用文件共享的能力。

### FTP的工作原理

#### 进程组成

- **主进程**：负责接收新的请求，打开熟知端口21（控制端口），使客户进程能够连接；
- **若干从属进程**：处理单个请求，处理完成后即终止。

#### 工作步骤

1. 主进程等待客户进程发送连接请求；
2. 启动从属进程处理客户进程的请求，主进程与从属进程并行执行；
3. 从属进程处理完请求后终止，主进程回到等待状态，继续接收其他客户进程的请求；
4. 注意：FTP服务器必须在整个会话期间保留用户的状态信息。

### 控制连接与数据连接

FTP工作时使用**两个并行的TCP连接**，具体区别如下：

| 连接类型 | 端口号 | 功能描述                                                                                                                       |
| -------- | ------ | ------------------------------------------------------------------------------------------------------------------------------ |
| 控制连接 | 21     | 传输控制信息（如连接请求、传送请求等），控制信息以7位ASCII格式传送；整个会话期间保持打开状态；服务器监听21号端口，等待客户连接 |
| 数据连接 | 20     | 传输文件数据；服务器端控制进程收到文件传输请求后，创建数据传送进程和数据连接；传送完毕后关闭数据连接并结束进程                 |

- 优势：使用两个不同端口号，使协议更简单、更易实现。

## 6.4 电子邮件

### 电子邮件系统的组成结构

电子邮件系统的核心组成包括三部分：

1. **用户代理(UA)**：用户与电子邮件系统的接口（如Outlook、Foxmail）；
2. **邮件服务器**：系统核心，负责发送和接收邮件，并向用户回报发送情况；
3. **邮件发送协议和读取协议**：
   - **SMTP**：邮件发送协议，用于用户代理向邮件服务器发送邮件，或在邮件服务器之间发送邮件；
   - **POP3**：邮件读取协议，用于用户代理从邮件服务器读取邮件。

### 电子邮件的收发过程

1. 发信人调用用户代理撰写邮件，用户代理用SMTP将邮件传送给发送方邮件服务器；
2. 发送方邮件服务器将邮件放入邮件缓存队列中，等待发送；
3. 发送方邮件服务器的SMTP客户进程，扫描到缓存中有待发送邮件后，向接收方邮件服务器的SMTP服务器进程发起TCP连接；
4. TCP连接建立后，SMTP客户进程向远程SMTP服务器进程发送邮件；所有邮件发送完毕后，SMTP关闭TCP连接；
5. 接收方邮件服务器的SMTP服务器进程收到邮件后，将邮件放入收信人的用户邮箱，等待收信人读取；
6. 收信人调用用户代理，使用POP3（或IMAP）协议从接收方邮件服务器的用户邮箱中取回邮件（若有新邮件）。

### 电子邮件格式与MIME

#### 电子邮件格式

电子邮件由**首部**和**主体**两部分组成：

- **首部**：包含关键字字段，其中：
  - `To`：必需字段，填入一个或多个收件人电子邮件地址；
  - `Subject`：可选字段，邮件主题，反映邮件主要内容；
  - `From`：必填字段，通常由邮件系统自动填入发件人地址；
  - 示例：`From: hoopdog@hust.edu.cn`、`To: abc@cskaoyan.com`、`Subject: Say hello to internet`；
- **主体**：邮件的具体内容，如“blahblah...”。

#### 多用途网际邮件扩充(MIME)

##### 背景

SMTP存在局限性：仅能传送一定长度的ASCII码，无法传送非英语文字（如中文）、可执行文件及其他二进制对象。

##### MIME内容

- 继续使用现有邮件格式，增加邮件主体的结构，定义非ASCII码的编码规则；
- 新增5个邮件首部字段，包括MIME版本、类型；
- 定义多种邮件内容格式，标准化多媒体电子邮件的表示方法；
- 定义传送编码，可转换任意内容格式，且不被邮件系统改变。

### 简单邮件传输协议(SMTP)

#### 概述

- 提供可靠且有效的电子邮件传输，控制两个通信的SMTP进程交换信息；
- 采用**客户/服务器**方式：发送邮件的SMTP进程是SMTP客户，接收邮件的SMTP进程是SMTP服务器；
- 使用TCP连接，端口号为**25**；
- 不使用中间邮件服务器，TCP连接直接在发送方和接收方邮件服务器之间建立；
- 发送方邮件服务器的SMTP客户，每隔一定时间扫描邮件缓存，发现待发送邮件后，用25号端口与接收方邮件服务器的SMTP服务器建立连接。

#### 通信阶段

1. **连接建立**：SMTP客户与接收方SMTP服务器建立TCP连接；
2. **邮件传送**：
   - 从 `MAIL`命令开始，`MAIL`命令后跟随发件人地址；若SMTP服务器准备好接收，返回“250 OK”；
   - SMTP客户端发送一个或多个 `RCPT`（收件人recipient缩写）命令，确认接收方系统是否做好接收准备，避免浪费通信资源；
   - 收到“OK”回答后，客户端发送 `DATA`命令，表示开始传输邮件内容；
3. **连接释放**：邮件发送完毕后，SMTP客户发送 `QUIT`命令；SMTP服务器返回“221（服务关闭）”，同意释放TCP连接。

#### SMTP缺点

1. 不能传送可执行文件或其他二进制对象；
2. 仅限于传送7位ASCII码，无法传送非英语国家文字；
3. SMTP服务器会拒绝超过一定长度的邮件。

### 邮局协议(POP3)

#### 概述

- 简单但功能有限的邮件读取协议，当前使用第3个版本（POP3）；
- 采用**客户/服务器**工作方式，传输层使用TCP，端口号为**110**；
- 用户读取邮件时，用户代理向邮件服务器发出请求，拉取用户邮箱中的邮件。

#### 工作方式

- **下载并保留**：邮件下载到用户代理后，在邮件服务器中保留副本；
- **下载并删除**：邮件下载到用户代理后，删除邮件服务器中的原邮件。

### 因特网报文存取协议(IMAP)

- 功能比POP3复杂的邮件接收协议；
- 允许用户代理创建文件夹、在不同文件夹之间移动邮件、在远程文件夹中查询邮件；
- IMAP服务器会维护会话用户的状态信息；
- 支持用户代理只获取报文的某些部分。

### 基于万维网的电子邮件

- 特点：用户浏览器与Hotmail、Gmail等邮件服务器之间的邮件发送/接收使用**HTTP**；不同邮件服务器之间传送邮件时使用**SMTP**。

## 6.5 万维网(WWW)

### WWW的概念与组成结构

#### 基本概念

- 万维网(WWW)：一个资源空间，其中的有用事物称为**资源**，由全域“统一资源定位符”(URL)标识；资源通过超文本传输协议(HTTP)传送给使用者，使用者通过单击链接获取资源。

#### 内核部分标准构成

1. **统一资源定位符(URL)**：标识万维网上的各种文档，使每个文档在万维网范围内具有唯一标识符；
2. **超文本传输协议(HTTP)**：应用层协议，使用TCP连接进行可靠传输，是万维网客户程序与服务器程序交互的必须遵守的协议；
3. **超文本标记语言(HTML)**：文档结构标记语言，用约定标记描述页面中的文字、声音、图像、视频等信息及格式。

### WWW工作流程

1. Web用户使用浏览器（指定URL）与Web服务器建立连接，并发送浏览请求；
2. Web服务器将URL转换为文件路径，返回信息给Web浏览器；
3. 通信完成，关闭连接。

### 超文本传输协议(HTTP)

#### 概述

- HTTP定义浏览器（万维网客户进程）如何向万维网服务器请求Web文档，以及服务器如何将文档传送给浏览器；
- 是**面向事务**的应用层协议；
- 规定浏览器与服务器之间请求和响应的格式与规则，是万维网可靠交换文件的重要基础；
- 每个万维网站点有一个服务器进程，持续监听TCP的**80号端口**（默认），监听到连接请求后与浏览器建立连接。

#### HTTP的操作过程

1. TCP连接建立后，浏览器向服务器发送请求获取Web页面的HTTP请求；
2. 服务器收到HTTP请求后，构建所请求Web页的必需信息，通过HTTP响应返回给浏览器；
3. 浏览器解释信息，显示Web页给用户；
4. TCP连接释放。

#### HTTP报文结构

HTTP报文分为两类：

- **请求报文**：从客户向服务器发送的请求报文；
- **响应报文**：从服务器向客户发送的回答报文。

#### 用户单击链接后发生的事件（按顺序）

1. 浏览器分析链接指向页面的URL；
2. 浏览器向DNS请求解析域名的IP地址；
3. 域名服务器DNS解析出IP地址；
4. 浏览器与该服务器建立TCP连接（默认端口号80）；
5. 浏览器发出HTTP请求：`GET /ch/index.html`；
6. 服务器通过HTTP响应把文件 `index.htm`发送给浏览器；
7. TCP连接释放；
8. 浏览器解释文件 `index.htm`，并将Web页显示给用户。

#### HTTP的特点

1. **无状态**：同一客户第二次访问同一服务器的页面时，服务器响应与第一次相同；该特性简化服务器设计，使服务器更易支持大量并发HTTP请求；可通过“Cookie+数据库”跟踪用户活动；
2. **传输层协议**：采用TCP保证数据可靠传输；
3. **连接方式**：既支持非持久连接，也支持持久连接（HTTP/1.1支持）；
4. **面向文本**：报文内容以文本形式传输。

#### 持久连接与非持久连接

| 连接类型               | 定义                                                                             |
| ---------------------- | -------------------------------------------------------------------------------- |
| 非持久连接             | 每个网页元素对象（如JPEG图形、Flash等）的传输，都需要单独建立一个TCP连接         |
| 持久连接               | 服务器发送响应后保持连接，同一客户与服务器可通过该连接传送后续HTTP请求与响应报文 |
| - 非流水线（持久连接） | 客户收到前一个响应后，才能发出下一个请求                                         |
| - 流水线（持久连接）   | 客户每遇到一个对象引用，就立即发出一个请求                                       |

#### HTTP的方法（操作）

| 方法    | 意义                          |
| ------- | ----------------------------- |
| GET     | 请求读取由URL标识的信息       |
| HEAD    | 请求读取由URL标识的信息的首部 |
| POST    | 给服务器添加信息（如注释）    |
| CONNECT | 用于代理服务器                |

#### HTTP的状态码

状态码用于表示服务器对请求的处理结果，分为5类：

- **1xx**：通知信息，如“请求收到”或“正在处理”；
- **2xx**：成功，如“接受”或“知道了”；
- **3xx**：重定向，如“完成请求需采取进一步行动”；
- **4xx**：客户差错，如“请求语法错误”或“无法完成请求”；
- **5xx**：服务器差错，如“服务器失效无法完成请求”。
