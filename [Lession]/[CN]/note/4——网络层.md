# 计算机网络第四章 网络层相关内容

## 4.1 网络层的功能

### 1. 网络互联与异构网络

- **异构网络**：具有不同的寻址方案、不同的网络接入机制、不同的差错处理方法、不同的路由选择机制等的网络。
- **网络互联**：将两个以上的计算机网络，通过一定的方法，用一种或多种通信处理设备（即中间设备）相互连接起来，以构成更大的网络系统。
- **中继系统分类**（按工作层次划分）：
  - **物理层中继系统**：设备为**中继器**。使用时仅扩大网络范围，从网络层角度看仍为同一个网络，不称为网络互联。
  - **数据链路层中继系统**：设备为**网桥或交换机**。与物理层中继系统类似，仅扩大网络，网络层视角下仍为同一网络，不称为网络互联。
  - **网络层中继系统**：设备为**路由器**。TCP/IP体系在网络互联上的核心做法是：在网络层（IP层）采用标准化协议，使相互连接的异构网络可实现互联。
  - **网络层以上的中继系统**：设备为**网关**。

### 2. 虚拟互联网络

- **概念**：又称逻辑互联网络。互联的物理网络异构性客观存在，但通过IP协议，可使这些性能各异的网络在网络层上呈现为一个统一的网络。
- **优点**：互联网上的主机通信时，如同在单一网络上通信，无需关注互联的具体异构细节（如编址方案、路由选择协议等）。

### 3. 路由与转发

- **核心概念区分**：
  - **路由选择**：确定分组传输的路径（“选路”），需按照复杂分布式算法，根据相邻路由器提供的网络拓扑变化信息，动态调整路径。
  - **分组转发**：当分组到达路由器时的具体动作（“转发”），处理通过路由器的数据流，关键操作包括**转发表查询**、**分组转发**及相关的队列管理、任务调度。
- **路由器核心动作**：根据转发表将用户的IP数据报从合适的端口转发出去。

### 4. 拥塞控制

- **拥塞定义**：在通信子网中，因分组过量导致网络性能下降的现象。
- **拥塞状态判断**：
  - 轻度拥塞：网络负载增加，吞吐量明显低于正常水平。
  - 拥塞状态：网络吞吐量随负载增大而下降。
  - 死锁状态：网络负载继续增大，吞吐量下降至零。
- **拥塞控制作用**：确保子网能够承载当前流量，避免因拥塞导致分组丢失或网络死锁。
- **拥塞控制实现方法**：
  - 优化主机、路由器及路由器内部的转发处理过程；
  - 注意：单一增加资源（如带宽、路由器端口）无法解决拥塞。
- **拥塞控制分类**：
- | 类型     |  原理                                                | 优点                             |
  | -------- | ---------------------------------------------------- | -------------------------------- |
  | 开环控制 | 设计网络时预先考虑拥塞因素，力求运行时不产生拥塞     | 静态预防，系统启动后无需中途修改 |
  | 闭环控制 | 通过监测系统监视拥塞，及时检测拥塞位置并传递拥塞信息 | 基于反馈环路，动态适应网络变化   |

### 5. 流量控制与拥塞控制的区别

- **流量控制**：抑制发送端发送速率，确保接收端来得及接收，是**点对点**的局部问题，仅涉及发送端和接收端。
- **拥塞控制**：确保通信子网能传送待传数据，是**全局性**问题，涉及网络中所有主机、路由器及导致传输能力下降的因素。

## 4.2 路由算法

### 1. 静态路由与动态路由

| 类型                             | 概念                                                                 | 优点                                           | 缺陷/缺点                                                      | 使用范围                           |
| -------------------------------- | -------------------------------------------------------------------- | ---------------------------------------------- | -------------------------------------------------------------- | ---------------------------------- |
| 静态路由算法（非自适应路由算法） | 由网络管理员手工配置路由信息；拓扑或链路状态变化时，需手工修改路由表 | 简便、可靠，负荷稳定、拓扑变化小的网络中效果好 | 大型复杂网络不宜采用；管理员难全面掌握拓扑；变化后需大范围调整 | 高度安全的军事系统、较小的商业网络 |
| 动态路由算法（自适应路由算法）   | 路由器通过相邻路由器交换信息，按算法优化路由表；路由信息定期更新     | 改善网络性能，有助于流量控制                   | 算法复杂，增加网络负担；可能因反应过快振荡或过慢影响一致性     | 大多数动态变化的网络（如互联网）   |

### 2. 动态路由算法分类

#### （1）距离-向量路由算法

- **原理**：所有结点定期将完整路由选择表传送给直接相邻的结点。
- **路由选择表内容**：每条路径的目的地（另一结点）、路径的代价（也称距离）。
- **更新路由表的条件**：
  1. 收到的路由信息中，存在一条到达某目的地的路由，且距离（代价）短于当前使用的路由。
  2. 收到一条新路由，且该路由在本地路由表中不存在。
- **缺点**：容易出现**路由环路**问题。
- **典型算法**：RIP协议（采用“跳数”作为距离的度量单位）。

#### （2）链路状态路由算法

- **原理**：
  1. 主动测试所有邻接结点的状态。
  2. 定期将链路状态（与相邻路由器的连接状态）通过**泛洪法**传播给所有其他结点（泛洪法：信息先发送给相邻路由器，再由相邻路由器转发给其相邻路由器，直至全网）。
- **特点**：
  1. 发送的信息仅为路由器自身相邻的链路状态（非完整路由表）。
  2. 仅当链路状态发生变化时，才向全网发送消息。
  3. 每个路由结点使用相同原始状态数据独立计算路径，不依赖中间结点。
- **优点**：
  1. 链路状态报文不修改传播，易查找故障。
  2. 结点接收全网报文后可本地计算正确通路，保证一步汇聚。
  3. 规模可伸展性优于距离-向量算法。
- **典型算法**：OSPF协议，适用于大型或路由信息变化需快速汇聚的互联网环境。

### 3. 层次路由

- **背景**：网络规模扩大时，路由器路由表成比例增大，消耗更多缓冲区空间、CPU时间和带宽（用于交换路由信息）。
- **路由选择协议分类**：
  - **内部网关协议（IGP）**：自治系统（AS）内部使用的路由选择协议，如RIP、OSPF。
  - **外部网关协议（EGP）**：不同自治系统的路由器之间交换路由信息的协议，负责为分组在不同AS间选择最优路径，如BGP。
- **层次路由特点**：每个路由器仅需知道本区域内的路由细节，无需了解其他区域的内部结构；但会增加交换信息的种类，使协议更复杂（如OSPF）。

## 4.3 IPv4

### 4.3.1 IPv4（上）：IPv4分组格式与分片

#### 1. IPv4概述

- IPv4（IP版本4）是目前普遍使用的IP协议，定义：
  1. 数据传送的基本单元——IP分组及其数据格式。
  2. 分组处理规则、错误控制规则。
  3. 非可靠投递思想（不保证分组一定到达）及关联的分组路由选择思想。

#### 2. IPv4分组格式（各字段含义）

| 字段            | 长度 | 含义                                                                                                        |
| --------------- | ---- | ----------------------------------------------------------------------------------------------------------- |
| 版本            | 4位  | IP版本，目前为4（IPv4）                                                                                     |
| 首部长度        | 4位  | 基本单位为4B，最大值60B（15×4B），最常用20B（无选项字段时）                                                |
| 总长度          | 16位 | 首部与数据之和的长度，基本单位1B，最大值65535B                                                              |
| 标识            | 16位 | 计数器，确保数据报片能正确组装为原数据报                                                                    |
| 标志            | 3位  | - 最低位MF：MF=1代表该分组是分片；MF=0代表最后一个分片 `<br>`- 中间位DF：DF=0代表可分片；DF=1代表不可分片 |
| 片偏移          | 13位 | 基本单位为8B，指出分片后该片在原分组中的相对位置                                                            |
| 首部校验和      | 16位 | 仅校验分组的首部，不校验数据部分                                                                            |
| 生存时间（TTL） | 8位  | 保证分组不循环：每次路由转发时TTL减1，TTL=0时丢弃分组                                                       |
| 协议            | 8位  | 指出分组使用的上层协议（6=TCP，17=UDP）                                                                     |
| 源地址          | 4B   | 发送方的IP地址                                                                                              |
| 目的地址        | 4B   | 接收方的IP地址                                                                                              |

#### 3. IP数据报分片

- **MTU（最大传送单元）**：链路层数据报能承载的最大数据量（不同网络MTU不同）：
  - 以太网：1500B
  - 广域网：一般不超过576B
- **分片触发条件**：当IP数据报长度大于链路MTU时，需对其分片传输。
- **关键规则**：
  1. 分片仅在**目的地主机**进行组装，中间路由器不组装。
  2. 标志位作用：MF=1表示分片，DF=0允许分片。

#### 4. 网络层转发分组的流程

1. 提取目的主机的IP地址。
2. 查找路由表：
   - 找到目标路由：直接交付（同一网络）或根据路由表转发交付（不同网络）。
   - 未找到目标路由：发送给默认路由。
3. 若最终转发失败，报告分组转发出错。

### 4.3.2 IPv4（中）：IP地址、NAT与子网划分

#### 1. IPv4地址

- **定义**：连接到因特网的每台主机（或路由器）分配的32比特全球唯一标识符。
- **分类（基于前几位区分）**：

  | 地址类别 | 地址范围 | 前几位标识 | 结构                          | 用途           |
  | -------- | -------- | ---------- | ----------------------------- | -------------- |
  | A类      | 1~126    | 0          | 网络号（8位）+主机号（24位）  | 大型网络       |
  | B类      | 128~191  | 10         | 网络号（16位）+主机号（16位） | 中型网络       |
  | C类      | 192~223  | 110        | 网络号（24位）+主机号（8位）  | 小型网络       |
  | D类      | 224~239  | 1110       | 无网络号/主机号之分           | 组播地址       |
  | E类      | 240~255  | 1111       | 无网络号/主机号之分           | 保留为今后使用 |
- **特殊含义地址**：

  - 主机号全为1：本网络的**直接广播地址**（如202.98.174.255）。
  - 主机号全为0：表示本网络本身（如202.98.174.0）。
  - 127.0.0.0/8：**环路自检（Loopback Test）地址**，表示主机自身；目的地址为该段的IP数据报不会出现在网络上。
  - 255.255.255.255：**受限广播地址**，仅在本网络广播（路由器隔离广播域）。
  - 0.0.0.0：表示本网络上的本主机。

#### 2. 网络地址转换（NAT）

- **概述**：通过将专用网络地址（如Intranet）转换为公用地址（如Internet），对外隐藏内部IP地址的技术。
- **优点**：
  1. 节省IP地址：仅需1个全球IP地址即可连通因特网，专用网本地IP可重用。
  2. 提高安全性：隐藏内部网络结构，降低被攻击风险。
- **具体实现**：本地地址主机与外界通信时，NAT路由器通过**NAT转发表**完成“本地地址→全球地址”或“全球地址→本地地址”的转换。
- **与普通路由器的区别**：
- | 对比项       | 普通路由器                | NAT路由器                  |
  | ------------ | ------------------------- | -------------------------- |
  | IP地址修改   | 转发时不改变源/目的IP地址 | 转发时必须更换IP地址       |
  | 工作层次     | 仅工作在网络层            | 需查看和转换传输层的端口号 |

#### 3. 子网划分

- **背景（两级IP地址的缺点）**：
  1. IP地址空间利用率低。
  2. 路由表过大，影响网络性能。
  3. 灵活性差。
- **划分思路**：将两级IP地址（网络号+主机号）改为三级（网络号+子网号+主机号），从主机号中借用若干比特作为子网号（主机号相应减少）。
- **关键注意事项**：
  1. 子网划分仅为单位内部操作，对外仍表现为未划分子网的网络。
  2. 子网号全为0和全为1不可用（全为0表示本网络，全为1表示子网广播地址）。
  3. 主机号全为0和全为1的规则仍适用（全为0表示子网本身，全为1表示子网广播）。

#### 4. 子网掩码

- **作用**：表达对原网络主机号的借位，区分IP地址中的网络号+子网号与主机号。
- **默认子网掩码（未划分子网时）**：
  - A类：255.0.0.0
  - B类：255.255.0.0
  - C类：255.255.255.0
- **使用规则**：同一子网的所有主机及路由器相应端口，必须设置相同的子网掩码；主机设置IP地址时需同时设置子网掩码。

#### 5. 无分类域间路由选择（CIDR）

- **概述**：在变长子网掩码基础上，消除传统A/B/C类地址划分，支持超网构造的IP地址划分方法。
- **核心结构**：IP地址 = <网络前缀 + 主机号>，通过网络前缀长度（如/24表示前24位为网络前缀）表示子网掩码。
- **特点**：
  1. 将网络前缀相同的连续IP地址组成**CIDR地址块**，实现地址聚合（路由聚合/超网）。
  2. 消除传统地址分类，提高IPv4地址空间利用率。
  3. 网络前缀越长，地址块越小，路由越具体；前缀长度灵活。
- **优点**：减少路由器间路由信息交换量，提高网络性能。
- **路由查找方法**：使用**二叉线索树**结构。

### 4.3.3 IPv4（下）：ARP、DHCP与ICMP

#### 1. IP地址与硬件地址的区别

| 对比项     | IP地址                             | 硬件地址（如MAC地址）                     |
| ---------- | ---------------------------------- | ----------------------------------------- |
| 层次       | 网络层地址，分层次等级             | 数据链路层地址，平面式（无层次）          |
| 使用场景   | 网络层及以上层次，放在IP数据报首部 | 数据链路层，放在MAC帧首部                 |
| 可见性     | 数据链路层看不见IP数据报中的IP地址 | 数据链路层直接使用                        |
| 路由器使用 | 路由器间传输时使用IP地址           | 到达目标网络后，用MAC地址查找目标物理主机 |

- **路由器的地址特性**：拥有多个IP地址（每个端口对应一个网络的IP）和多个硬件地址（每个端口对应一个MAC地址）。

#### 2. 地址解析协议（ARP）

- **作用**：实现IP地址到MAC地址的映射。
- **ARP表**：每台主机/路由器的ARP高速缓存，存储本局域网上各主机和路由器的IP→MAC映射表（动态更新）。
- **不同发送场景的ARP使用**：
  1. 发送方为**主机**，目标主机在**本网络**：用ARP找到目标主机的MAC地址。
  2. 发送方为**主机**，目标主机在**其他网络**：用ARP找到本网络路由器的MAC地址，后续由路由器转发。
  3. 发送方为**路由器**，目标主机在**本网络**：用ARP找到目标主机的MAC地址。

#### 3. 动态主机配置协议（DHCP）

- **概述**：应用层协议（基于UDP），提供即插即用联网机制，允许计算机加入新网络时自动获取IP地址，无需手工配置。
- **实现过程（广播交互）**：
  1. DHCP客户机广播**“DHCP发现”** 消息，寻找DHCP服务器。
  2. DHCP服务器广播**“DHCP提供”** 消息，包含分配的IP地址及配置信息。
  3. DHCP客户机接收后，广播**“DHCP请求”** 消息，确认接受该IP。
  4. DHCP服务器广播**“DHCP确认”** 消息，完成IP分配。
- **注意事项**：
  1. DHCP客户端与服务器必须通过广播交互（因客户机初始无IP）。
  2. 分配的IP地址是**临时的**，客户机仅能在有限时间内使用（租期）。

#### 4. 网际控制报文协议（ICMP）

- **目的**：在网络层报告差错和异常情况，提高IP数据报交付成功率。

##### （1）ICMP报文种类

- **ICMP差错报告报文**（5类）：

  1. 终点不可达：路由器/主机无法交付数据报时，向源点发送。
  2. 源点抑制：因拥塞丢弃数据报时，向源点发送，要求降低发送速率。
  3. 时间超过：路由器收到TTL=0的数据报时，丢弃并向源点发送。
  4. 参数问题：数据报首部字段值错误时，丢弃并向源点发送。
  5. 改变路由（重定向）：路由器通知主机下次将数据报发送到更优路由器。
- **ICMP询问报文**（4类）：

  1. 回送请求和回答：测试主机连通性（如PING）。
  2. 时间戳请求和回答：同步两台主机的时间。
  3. 掩码地址请求和回答：主机获取本地子网掩码。
  4. 路由器询问和通告：主机发现局域网内的路由器。

##### （2）不应发送ICMP差错报告的情况

1. 对ICMP差错报告报文，不再发送ICMP差错报告。
2. 对第一个分片的后续所有数据报片，不发送ICMP差错报告。
3. 对组播地址的数据报，不发送ICMP差错报告。
4. 对特殊地址（127.0.0.0/8、0.0.0.0）的数据报，不发送ICMP差错报告。

##### （3）ICMP的应用

- **PING**：测试两台主机连通性，使用ICMP**回送请求和回答报文**。
- **Traceroute**：跟踪分组经过的路由，使用ICMP**时间超过报文**（每跳TTL减1，超时后返回时间超过报文，从而定位路由）。

## 4.4 IPv6

### 1. IPv6的背景与主要特点

- **背景**：解决IPv4地址耗尽问题（缓解方法：超网聚合、NAT；根本方法：IPv6）。
- **主要特点**：
  1. **更大的地址空间**：从IPv4的32位扩展到128位。
  2. **扩展的地址层次结构**：支持更灵活的网络分层。
  3. **灵活的首部格式**：可选字段移至扩展首部，简化基本首部。
  4. **改进的选项**：支持更多可选功能。
  5. **允许协议继续扩充**：便于后续功能升级。
  6. **支持即插即用**（自动配置）：无需手工设置IP。
  7. **支持资源预分配**：适合实时业务（如语音、视频）。
  8. **分片规则优化**：仅源结点可分片（端到端），传输路径中的路由器不能分片。
  9. **首部长度规则**：必须是8B的整数倍（IPv4为4B的整数倍）。
  10. **增强安全性**：身份验证和保密功能为关键特征。

### 2. IPv6地址

- **基本类型**：

  1. **单播**：传统点对点通信，一对一交付。
  2. **多播**：一点对多点通信，分组交付到组内所有主机。
  3. **任播**：IPv6新增类型，分组交付到组内最近的一台主机（一对一映射）。
- **地址缩写规则**：

  1. 16位域的开头连续0可省略，但域中至少保留1个数字（如2001:0DB8:: → 2001:DB8::）。
  2. 相继的全0域可使用双冒号（::）缩写，但整个地址中仅允许1次双冒号（如FF01:0:0:0:0:0:0:1 → FF01::1）。

### 3. IPv4向IPv6过渡的技术

- **双协议栈技术**：设备同时装有IPv4和IPv6协议栈，可同时与IPv4、IPv6网络通信。
- **隧道技术**：将整个IPv6数据报封装到IPv4数据报的数据部分，使IPv6数据报能在IPv4网络中传输（“隧道”穿越IPv4网络）。

## 4.5 路由协议

### 4.5.1 路由协议（上）：自治系统与RIP

#### 1. 自治系统（AS）

- **概述**：单一技术管理下的一组路由器，内部使用**同一IGP**和**共同度量**确定分组路由，外部使用**EGP**确定AS间的分组路由。

#### 2. 域内路由与域间路由

| 类型                          | 定义                                                         | 协议示例  |
| ----------------------------- | ------------------------------------------------------------ | --------- |
| 内部网关协议（IGP，域内路由） | 自治系统内部使用的路由选择协议，用于AS内路由器间交换路由信息 | RIP、OSPF |
| 外部网关协议（EGP，域间路由） | 不同AS的路由器间交换路由信息的协议，用于选择AS间的最优路径   | BGP-4     |

#### 3. 路由信息协议（RIP）

- **简介**：最早广泛应用的IGP，分布式基于**距离-向量**的路由选择协议，核心优点是简单。
- **实现细节**：
  1. **距离度量**：以“跳数”为单位，每经过一个路由器为1跳，最大跳数15（16表示不可达）。
  2. **更新机制**：每30秒广播一次RIP路由更新信息，建立并维护动态路由表。
  3. **子网掩码要求**：RIP协议中每个网络的子网掩码必须相同。
- **特点**：
  1. 仅与**相邻路由器**交换信息。
  2. 交换的信息是当前路由器的**完整路由表**（自身知道的所有路由）。
  3. 按固定时间间隔（30秒）交换路由信息。
- **缺陷**：
  1. 网络规模受限（最大15跳）。
  2. 网络越大，路由表交换开销越大（交换完整路由表）。
  3. 网络故障时收敛慢（“坏消息传得慢”，需长时间扩散到所有路由器）。
- **优点**：实现简单、开销小、收敛过程较快（小规模网络中）。

### 4.5.2 路由协议（中）：OSPF

#### 1. OSPF简介

- 开放最短路径优先（OSPF）是基于**链路状态**的IGP，分布式链路状态路由算法的典型代表。

#### 2. OSPF实现细节

- **信息传播方式**：使用**洪泛法**向本AS内所有路由器发送信息（非仅相邻路由器）。
- **发送的信息内容**：仅为当前路由器相邻的所有路由器的**链路状态**（非完整路由表）。
- **更新时机**：仅当链路状态发生变化时，才用洪泛法发送更新消息（无固定时间间隔）。
- **协议层次**：OSPF是网络层协议，直接使用IP数据报传送（不依赖UDP/TCP）。

#### 3. OSPF特点

1. **灵活的代价设置**：对不同链路，可根据IP分组的服务类型（TOS）设置不同代价，支持不同业务的路由计算。
2. **负载平衡**：若到同一目的网络有多条相同代价的路径，可将流量分配到多条路径。
3. **安全性**：所有OSPF路由器间交换的分组均有鉴别功能，仅可信赖路由器间交换链路状态信息。
4. **支持CIDR**：支持可变长度子网划分和无分类编址。
5. **链路状态序号**：每个链路状态带32位序号，序号越大状态越新，避免旧信息覆盖新信息。
6. **路由计算算法**：使用**迪杰斯特拉算法**计算最短路径。

#### 4. OSPF分组类型

1. **问候分组**：发现和维持邻站的可达性。
2. **数据库描述分组**：向邻站提供自身链路状态数据库的摘要信息。
3. **链路状态请求分组**：向邻站请求特定链路状态项目的详细信息。
4. **链路状态更新分组**：用洪泛法向全网更新链路状态（核心分组）。
5. **链路状态确认分组**：对链路更新分组的确认，确保信息可靠传输。

### 4.5.3 路由协议（下）：BGP与协议比较

#### 1. 边界网关协议（BGP）

- **简介**：EGP的核心协议（目前为BGP-4），用于不同AS的路由器间交换路由信息，是**应用层协议**（基于TCP，确保传输可靠）。
- **核心角色**：**BGP发言人**——每个AS的管理员选择至少一个路由器作为BGP发言人，负责与其他AS的BGP发言人交换路由信息。

#### 2. BGP工作原理

1. 两个AS的BGP发言人先建立**TCP连接**（端口179），形成BGP会话。
2. 通过BGP会话交换路由信息：
   - 初始运行时，交换**完整BGP路由表**。
   - 后续仅交换**变化的路由信息**（增量更新）。
3. 所有BGP发言人交换网络可达性信息后，各发言人计算到达其他AS的“较好路由”（非最优，因需考虑政策、带宽等因素）。

#### 3. BGP特点

1. **交换粒度**：交换的路由信息以AS为单位，结点数量级为AS数量级（远少于AS内网络数），开销小。
2. **支持CIDR**：与OSPF类似，支持无分类编址。
3. **可靠性**：基于TCP传输，避免路由信息丢失。
4. **政策灵活性**：可根据AS间的政策（如商业合作、安全策略）选择路由，而非仅按“最短路径”。

#### 4. BGP报文类型

1. **打开（Open）报文**：与相邻BGP发言人建立关系，包含AS号、BGP版本等信息。
2. **更新（Update）报文**：发送某一路由的信息，或列出要撤销的多条路由。
3. **保活（Keepalive）报文**：确认Open报文，周期性（如30秒）证实邻站关系（无路由信息时发送）。
4. **通知（Notification）报文**：发送检测到的差错（如TCP连接中断、路由信息错误），发送后关闭BGP会话。

#### 5. 路由协议比较表

| 协议 | 类型        | 路由算法  | 传递协议 | 路径选择依据         | 交换结点            | 交换内容                                 |
| ---- | ----------- | --------- | -------- | -------------------- | ------------------- | ---------------------------------------- |
| RIP  | 内部（IGP） | 距离-向量 | UDP      | 跳数最少             | 仅相邻路由器        | 完整路由表（每30秒一次）                 |
| OSPF | 内部（IGP） | 链路状态  | IP       | 代价最低             | 本AS内所有路由器    | 仅自身相邻的链路状态（仅状态变化时发送） |
| BGP  | 外部（EGP） | 路径-向量 | TCP      | 较好路由（政策优先） | 仅相邻AS的BGP发言人 | 首次：完整路由表；后续：仅变化的路由信息 |

## 4.6 IP组播

### 1. 组播的概念与优点

- **概念**：源计算机一次发送单个分组，通过组播地址标识，使分组抵达多个目标主机（一对多）。主机需通过**IGMP协议**加入组播组，路由器需支持组播协议（称为**组播路由器**）。
- **核心特点**：组播仅应用于UDP（TCP为点对点，不支持组播）。
- **优点**：数据仅发送一次，减轻网络负载和发送者负担（无需向每个接收者单独发送）。

### 2. IP组播地址

- **地址类型**：使用IPv4的**D类地址**（224.0.0.0~239.255.255.255）标识组播组。
- **组播数据报与普通IP数据报的区别**：
  1. 组播数据报为“尽最大努力交付”，不提供可靠交付。
  2. 组播地址仅能作为**目的地址**，不能作为源地址。
  3. 不对组播数据报产生ICMP差错报文（如PING组播地址无响应）。
  4. 并非所有D类地址都可用（部分为预留地址）。

### 3. 硬件组播与过滤

- **硬件地址映射**：组播数据报在局域网中需通过硬件组播交付，D类IP地址与MAC地址存在映射关系，但映射非唯一（多个IP组播地址可能映射到同一MAC组播地址）。
- **软件过滤**：主机收到组播数据报后，需在IP层通过软件过滤，丢弃非本主机所属组播组的数据报。

### 4. 因特网组管理协议（IGMP）

- **用途**：使路由器知道局域网内组播组的成员信息（“哪些主机属于哪个组播组”）。
- **特点**：TCP/IP体系的一部分，运行在主机与本地组播路由器之间。
- **工作阶段**：
  1. **加入阶段**：主机加入新组播组时，向该组播地址发送IGMP报文，声明成员身份。
  2. **维护阶段**：本地组播路由器定期（如125秒）探询局域网内主机，确认组播组是否仍有成员：
     - 若有主机响应，路由器认为该组播组活跃，继续向其他组播路由器转发成员关系。
     - 多次探询无响应，路由器停止转发该组播组的成员关系。

### 5. 组播路由算法

- 实现因特网组播需专用路由算法，常见类型：
  1. 基于链路状态的路由选择。
  2. 基于距离-向量的路由选择。
  3. 协议无关的组播（PIM）：可建立在任何路由器协议（如RIP、OSPF）之上，灵活性高。

## 4.7 移动IP

### 1. 移动IP的概念与功能实体

- **概念**：支持移动结点（计算机、服务器等）在移动中保持网络连接性的体系与协议，使移动结点以**固定IP地址**跨越不同网段漫游，且网络权限不改变。
- **三种功能实体**：
  1. **移动结点**：具有永久IP地址的移动设备（如笔记本电脑）。
  2. **本地代理（归属代理）**：移动结点的“永久居所”（归属网络）中的实体，负责根据移动结点的**转交地址**（临时位置地址），通过隧道技术转交数据包。
  3. **外部代理**：移动结点所在外地网络中的实体，帮助移动结点完成移动管理（如获取转交地址）。

### 2. 移动IP与动态IP的区别

| 对比项     | 移动IP                               | 动态IP（DHCP分配）                             |
| ---------- | ------------------------------------ | ---------------------------------------------- |
| IP地址特性 | 移动结点使用**固定IP地址**     | 主机每次联网可能获取**不同的临时IP地址** |
| 核心功能   | 支持跨网段漫游，保持连接性与网络权限 | 仅解决IP地址自动分配，不支持漫游               |
| 应用场景   | 移动设备（如手机、笔记本）跨网络访问 | 固定局域网内的主机（如家用电脑、办公电脑）     |

### 3. 移动IP通信过程

1. **移动结点在本地网时**：按传统TCP/IP方式通信（使用固定IP地址）。
2. **移动结点进入外地网时**：
   - 向本地代理注册当前的**转交地址**（类似“呼叫转移”设置）。
   - 本地代理截获发往移动结点固定IP的数据包，通过隧道技术发送到转交地址。
   - 转交地址接收数据包后，恢复为原数据并发送给移动结点。
3. **移动结点更换外地网时**：仅需向本地代理更新注册的转交地址，即可继续通信。
4. **移动结点回到本地网时**：向本地代理注销转交地址，恢复传统TCP/IP通信。

## 4.8 网络层设备（路由器）

### 1. 路由器的核心任务与工作过程

- **核心任务**：
  1. 隔离**广播域**（区别于网桥隔离碰撞域、集线器不隔离任何域）。
  2. 连接**异构网络**（如以太网与广域网）。
  3. 完成**路由转发**（根据路由表将IP数据报转发到正确路径）。
- **工作过程**：
  1. 若源主机与目标主机在**同一网络**：直接交付（无需转发）。
  2. 若源主机与目标主机在**不同网络**：路由器根据转发表，将数据报转发给下一个路由器（间接交付），直至到达目标网络。

### 2. 路由器的组成与功能

路由器分为**路由选择部分**（控制部分）和**分组转发部分**（数据部分）：

#### （1）路由选择部分（控制部分）

- **核心构件**：路由选择处理机。
- **任务**：
  1. 根据选定的路由协议（如RIP、OSPF）构造路由表。
  2. 与相邻路由器交换路由信息，定期更新和维护路由表。

#### （2）分组转发部分（数据部分）

- **组成**：
  1. **交换结构**：根据转发表处理分组，将输入端口的分组转发到合适的输出端口，交换方法包括：
     - 通过存储器交换
     - 通过总线交换
     - 通过互联网络交换
  2. **一组输入端口**：从物理层接收比特流，提取链路层帧，再从帧中提取网络层IP数据报。
  3. **一组输出端口**：将IP数据报转换为比特流，发送到物理层。
- **核心功能**：
  1. 处理通过路由器的数据流。
  2. 关键操作：转发表查询、分组转发、队列管理、任务调度。

### 3. 路由器与网桥的区别

| 对比项       | 路由器                                  | 网桥（数据链路层设备）                       |
| ------------ | --------------------------------------- | -------------------------------------------- |
| 工作层次     | 网络层                                  | 数据链路层                                   |
| 协议相关性   | 面向协议，依赖IP地址操作                | 与高层协议无关，依赖MAC地址操作              |
| 核心功能     | 路由选择、IP分片、帧格式转换、TTL控制等 | 仅实现MAC帧的转发与过滤，隔离碰撞域          |
| 支持网络类型 | 可连接异构网络（如以太网、广域网）      | 仅可连接同类型链路（如以太网与以太网）       |
| 广播域隔离   | 隔离广播域（不转发广播包）              | 不隔离广播域（转发广播包，可能导致广播风暴） |

### 4. 路由表与路由转发

#### （1）路由表

- **功能**：实现路由选择，存储到达不同目的网络的路径信息。
- **结构**：
- 包含4个核心字段：
- | 字段             | 含义                                 |
  | ---------------- | ------------------------------------ |
  | 目的网络IP地址   | 数据报的目标网络IP（非单个主机IP）   |
  | 子网掩码         | 区分目的网络的网络前缀与主机号       |
  | 下一跳IP地址     | 数据报应转发到的下一个路由器的IP地址 |
  | 接口             | 数据报应从路由器的哪个端口转发出去   |

#### （2）路由转发与路由选择的区别

- **路由转发**：仅涉及**单个路由器**，根据转发表（路由表简化版）将数据报从输入端口转发到输出端口，是“即时动作”。
- **路由选择**：涉及**多个路由器**，路由表是多个路由器通过路由协议（如RIP、OSPF）协同工作的结果，是“全局路径规划”。

#### （3）默认路由

- **目的**：减少转发表的重复项目，用一个默认路由代替所有“下一跳相同”的路由项（适用于小型网络，或作为路由表的补充）。
- **场景**：当路由器无法在路由表中找到目的网络时，将数据报转发到默认路由指向的下一跳路由器。

### 关键注意事项

- 若一个存储转发设备实现了某层功能，则可互联两个在该层次上使用不同协议的网段（如路由器实现网络层功能，可互联网络层协议不同的网络）。
- 转发表是路由表的简化版，仅包含转发所需的核心信息（如目的网络、下一跳、接口），不含路由协议相关的冗余信息。
