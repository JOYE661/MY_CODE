# 计算机网络第三章 数据链路层

## 一、数据链路层概述

数据链路层在物理层提供服务的基础上向网络层提供服务，其主要作用是加强物理层传输原始比特流的功能，将物理层提供的可能出错的物理连接改造为逻辑上无差错的数据链路，使之对网络层表现为一条无差错的链路。

数据链路层向网络层提供的三种服务如下：

1. **无确认的无连接服务**

   - 特点：源机器发送数据帧时不需先建立链路连接，目的机器收到数据帧时不需发回确认；对丢失的帧，数据链路层不负责重发，而交给上层处理。
   - 使用范围：适用于实时通信或误码率较低的通信信道（如以太网）。
2. **有确认的无连接服务**

   - 特点：源机器发送数据帧时不需先建立链路连接，但目的机器收到数据帧时必须发回确认；源机器在所规定的时间内未收到确认信号时，就重传丢失的帧，以提高传输的可靠性。
   - 使用范围：适用于误码率较高的通信信道（如无线通信）。
3. **有确认的面向连接服务**

   - 特点：帧传输过程分为三个阶段——建立数据链路、传输帧、释放数据链路；目的机器对收到的每一帧都要给出确认，源机器收到确认后才能发送下一帧；**有连接就一定要有确认，不存在无确认的面向连接的服务**。
   - 使用范围：适用于通信要求（可靠性、实时性）较高的场合。

## 二、3.1 数据链路层的功能

数据链路层的核心功能包括链路管理、帧定界/帧同步/透明传输、流量控制、差错控制，具体如下：

### 2.1 链路管理

- **概述**：数据链路层连接的建立、维持和释放过程称为链路管理，主要用于面向连接的服务。
- **实现过程**：
  1. 首先确认对方已处于就绪状态；
  2. 交换一些必要的信息以对帧序号初始化；
  3. 建立连接，在传输过程中维持连接，传输完毕后释放连接。

### 2.2 帧定界、帧同步与透明传输

#### （1）帧定界

- 概述：两个工作站之间传输信息时，必须将网络层的分组封装成帧，以帧的格式进行传送；将一段数据的前后分别加首部和尾部，就构成了帧，首部和尾部中的控制信息用于确定帧的界限。

#### （2）帧同步

- 概述：接收方应能从接收到的二进制比特流中区分出帧的起始与终止。

#### （3）透明传输

- 概述：采取有效措施解决“误认为传输结束而丢弃后面数据”的问题，确保数据中即使包含与帧定界符相同的比特组合，也能被正确传输。

### 2.3 流量控制

- **概述**：收发双方的工作速率和空间存在差异，可能出现“发方发送能力大于收方接收能力”的现象，若不进行流量控制会导致数据丢失。
- **实现**：通过控制发送方的发送速度，使接收方有足够的缓冲空间接收每个帧，从而实现流量控制。

### 2.4 差错控制

- **概述**：使发送方确定接收方是否正确收到由其发送的数据的方法，主要解决两类错误：
  - 位错：数据中的某些位出现错误；
  - 帧错：帧的丢失、重复或失序等错误。
- **解决方法**：
  - 解决位错：采用CRC循环冗余码；
  - 解决帧错：采用自动重传请求（ARQ）。

## 三、3.2 组帧

组帧的核心是：为使接收方能正确接收并检查所传输的帧，发送方需依据规则将网络层递交的分组封装成帧，解决帧定界、帧同步、透明传输等问题。常见组帧方法如下：

### 3.1 字符计数法

- **实现方法**：在帧头部使用一个计数字段，标明帧内字符数。
- **缺点**：若计数字段出错，收发双方将失去同步，导致后续数据传输错误。

### 3.2 字符填充的首尾定界符法

- **实现方法**：
  1. 使用特定字符定界一帧的开始（DLE STX）与结束（DLE ETX）；
  2. 若数据中出现特殊字符（DLE、STX、ETX），则在其前面填充一个转义字符（DLE），防止被误判为帧的首尾定界符。

### 3.3 零比特填充的首尾标志法

- **实现方法**：
  1. 使用特定比特模式“01111110”标志一帧的开始和结束；
  2. 发送信息时，遇到5个连续的“1”，就自动在后面加1个“0”；
  3. 接收信息时，遇到5个连续的“1”，就自动在后面删1个“0”。
- **优点**：容易由硬件实现，性能优于字符填充法。

### 3.4 违规编码法

- **使用条件**：仅适用于物理层采用冗余编码的特殊环境（如曼彻斯特编码）。
- **实现方法**：
  - 违规编码定义：在曼彻斯特编码中，比特“1”通常编码成“高-低”电平，比特“0”编码成“低-高”电平；若出现“高-高”或“低-低”电平，则视为“违规编码”；
  - 借用违规编码序列定界帧的起始和终止（如局域网IEEE 802标准）。

### 3.5 常用组帧方法

目前较常用的组帧方法是**零比特填充法**和**违规编码法**。

## 四、3.3 差错控制

差错产生的主要原因：信道固有噪声干扰（可通过提高信噪比解决）、外界冲击噪声（无法通过提高信号幅度降低干扰，是产生差错的重要原因）。差错控制主要通过编码技术实现，分为自动重传请求（ARQ）和前向纠错（FEC）两类。

### 4.1 基于编码技术的差错控制方式

1. **自动重传请求（ARQ）**：接收端检测出差错时，通知发送端重发，直到接收到正确的码字为止。
2. **前向纠错（FEC）**：接收端不仅能发现差错，还能确定比特串的错误位置，从而直接纠正错误。

### 4.2 检错编码

检错编码仅能检测错误，无法纠正错误，需配合ARQ使用。

#### （1）奇偶校验码

- 组成：由n-1位数据和1位校验位组成；
- 原理：校验位用于调节发送信息中“1”的个数——若为偶校验，“1”的总数为偶数；若为奇校验，“1”的总数为奇数。

#### （2）循环冗余码（CRC）

- 原理：任何二进制数位串都可与一个仅含0和1系数的多项式建立一一对应关系（设m位数据对应的多项式为M(x)）。
- **计算步骤**：
  1. 加0：假设生成多项式G(x)的阶为r，在帧的低位端加r个0；
  2. 模2除：用G(x)对应的数据串去除步骤1中得到的数据串，所得余数即为冗余码（共r位，前面的0不可省略）。

### 4.3 纠错编码（海明码）

- **原理**：在有效信息位中加入若干校验位形成海明码，将海明码的每个二进制位分配到多个奇偶校验组中；某一位出错后，会引起相关校验位的值变化，从而既能发现错位，又能指出错位位置。
- **计算过程**：
  1. 确定校验位个数：设n为有效信息位数，k为校验位位数，需满足公式 \(2^k \geq n + k + 1\)；
  2. 确定校验位分布：校验位位于海明位号为 \(2^0, 2^1, ..., 2^{k-1}\) 的位置，其余位为信息位；
  3. 分组形成校验关系：被校验数据位的海明位号等于校验该数位的各校验位海明位号之和；
  4. 校验位取值：校验位的值为对应组内所有位的异或结果。

## 五、3.4 流量控制与可靠传输机制

### 5.1 停止-等待流量控制

- **基本原理**：每次只允许发送一帧，发送后等待接收方的确认信息；若接收方不反馈应答信号，发送方需一直等待。
- **特点**：传输效率很低，仅适用于数据量小、误码率低的场景。

### 5.2 滑动窗口流量控制

滑动窗口机制通过“发送窗口”和“接收窗口”控制帧的发送与接收，实现高效的流量控制。

#### （1）核心概念

- 发送窗口：发送方持有的连续允许发送的帧序号范围，大小代表“未收到确认时最多可发送的帧数”；
- 接收窗口：接收方持有的连续允许接收的帧序号范围，用于控制“可接收”与“不可接收”的帧。

#### （2）机制特点

- 接收窗口大小为1时，可保证帧的有序接收；
- 只有接收窗口向右滑动（接收方发送确认）时，发送窗口才可能向右滑动（发送方收到确认）。

### 5.3 可靠传输机制

可靠传输依赖**确认**和**超时重传**两种核心机制：

- 确认：分为“无数据控制帧”（仅告知发送方“数据已正确接收”）和“捎带确认”（将确认信息带在回复帧中，提高传输效率）；
- 超时重传：发送方发送数据帧后开启计时器，若规定时间内未收到确认，则重传该帧，直到发送成功。

### 5.4 滑动窗口协议（ARQ协议）

滑动窗口技术与请求重发技术结合，形成三类常用ARQ协议：

#### （1）停止-等待ARQ

- 本质：发送窗口和接收窗口大小均为1的滑动窗口协议；
- 帧缓冲区：发送方需在缓存中保留已发送帧的副本，直到收到确认（用于超时重传和判定重复帧）；
- 特殊场景处理：若“数据帧正确但确认帧破坏”，发送方会重传已被接收的数据，接收方丢弃重复帧并重新发送确认。

#### （2）后退N帧ARQ（GBN）

- 特点：连续发送多帧，提高信道利用率；
- 窗口大小：发送窗口最大为 \(2^n - 1\)（n为帧编号的比特数），接收窗口大小为1；
- 重传机制：接收方仅按顺序接收帧，若检测出失序帧，要求发送方重发“最后一个正确接收帧之后的所有未确认帧”；
- 计时器：每个发送缓冲区对应一个计时器，超时则重传该缓冲区的帧；
- 确认方式：累积确认（仅确认“序号最大的按序到达帧”）；
- 缺点：若信道误码率高，重传帧数多，性能可能不如停止-等待ARQ。

#### （3）选择性重传ARQ（SR）

- 特点：仅重传“出错的帧”，而非“所有未确认帧”，提高信道利用率；
- 窗口大小：发送窗口和接收窗口大小均为 \(2^{n-1}\)（n为帧编号的比特数）；
- 缓冲区：接收方需设置大容量缓冲区，暂存未按序正确收到的帧；
- 缺点：需额外存储空间存储暂存帧，实现复杂度高于GBN。

## 六、3.5 介质访问控制（MAC）

介质访问控制子层（MAC）的核心任务是“协调广播信道中各结点的传输”，避免冲突，主要分为三类方法：**信道划分介质访问控制**、**随机访问介质访问控制**、**轮询访问介质访问控制**。

### 6.1 信道划分介质访问控制（静态划分信道）

通过“多路复用技术”将物理信道划分为多个子信道，分配给不同结点，实现“隔离信号、共享信道资源”，提高信道利用率。

| 复用技术            | 实现原理                                                 | 优点                             | 缺点                                   | 优化/扩展                                                                            |
| ------------------- | -------------------------------------------------------- | -------------------------------- | -------------------------------------- | ------------------------------------------------------------------------------------ |
| 频分多路复用（FDM） | 将多路基带信号调制到不同频率载波上，叠加形成复合信号     | 充分利用传输介质带宽，系统效率高 | 需在相邻子信道间加“保护带”，防止干扰 | -                                                                                    |
| 时分多路复用（TDM） | 将物理信道按时间分成若干时间片，轮流分配给多个信号       | -                                | 计算机数据具有突发性，子信道利用率低   | 统计时分复用（STDM）：按需动态分配时隙，提高利用率                                   |
| 波分多路复用（WDM） | 在一根光纤中传输多种不同波长的光信号，波长不同则互不干扰 | 适用于光纤通信，容量大           | -                                      | 本质是“光域的FDM”                                                                  |
| 码分多路复用（CDM） | 用不同编码区分各路信号，既共享频率又共享时间             | 抗干扰能力强，支持多用户同时传输 | 实现复杂度高                           | 码分多址（CDMA）：发送1时传“码片序列”，发送0时传“码片序列反码”，各站码片序列正交 |

### 6.2 随机访问介质访问控制（动态分配信道）

所有用户可随机发送信息，占用信道全部速率，需通过协议减少冲突。

#### （1）ALOHA协议

- 纯ALOHA：任何结点需发送数据时直接发送，未收到确认则等待随机时间重发；缺点是冲突概率高，吞吐量低。
- 时隙ALOHA：时间划分为等长时隙，仅允许在时隙开始时发送帧；减少冲突概率，但仍存在“不同结点在同时隙发送”的冲突。

#### （2）CSMA协议（载波侦听多路访问）

核心思想：发送前先侦听信道，根据信道状态决定是否发送，减少冲突。

| CSMA类型   | 工作原理                                                         | 优点                           | 缺点                       |
| ---------- | ---------------------------------------------------------------- | ------------------------------ | -------------------------- |
| 1-坚持CSMA | 侦听信道→空闲则立即发送→忙则持续侦听→冲突则随机等待后重侦听   | 减少冲突可能性，提高利用率     | 传播时延影响大，仍存在冲突 |
| 非坚持CSMA | 侦听信道→空闲则立即发送→忙则放弃侦听，随机等待后重侦听         | 降低“多结点同时发送”的冲突率 | 增加数据在网络中的延迟     |
| p-坚持CSMA | 侦听信道→忙则持续侦听→空闲则以概率p发送、概率1-p推迟到下一时隙 | 平衡冲突率和延迟               | 实现复杂度较高             |

#### （3）CSMA/CD协议（载波侦听多路访问/碰撞检测）

- 适用场景：总线形以太网（有线局域网）；
- 核心思想：“发送前侦听，边发送边侦听”，一旦检测到碰撞立即停止发送；
- 关键参数：
  - 争用期：以太网端到端的往返时间，只有度过争用期才能确定传输无冲突；
  - 最小帧长：\(最小帧长 = 总线传播时延 \times 数据传输率 \times 2\)（确保在帧发送完毕前检测到冲突）；
- 碰撞解决：二进制指数退避算法——设重传次数为k，取随机数r（0≤r<2^k），退避等待时间为“r×争用期”；重传16次失败则丢弃帧并上报高层。

#### （4）CSMA/CA协议（载波侦听多路访问/碰撞避免）

- 适用场景：无线局域网（802.11a/b/g/n等），因无线信道“信号强度动态范围大”“存在隐蔽站问题”，无法使用CSMA/CD；
- 碰撞避免机制：
  1. 预约信道：发送方告知其他结点“传输所需时间”，让其他结点在该时间段内不发送；
  2. ACK帧：接收方正确接收数据帧（除广播/组播帧）后，必须发送ACK；未收到ACK则重传；
  3. RTS/CTS帧（可选）：解决隐藏站问题，发送方先发RTS（请求发送），接收方回复CTS（允许发送），其他结点收到则推迟发送。

#### （5）CSMA/CD与CSMA/CA的核心区别

| 对比维度 | CSMA/CD                  | CSMA/CA                      |
| -------- | ------------------------ | ---------------------------- |
| 冲突处理 | 可检测冲突，无法避免     | 无法检测冲突，通过机制避免   |
| 适用场景 | 总线形以太网（有线）     | 无线局域网（802.11）         |
| 检测方式 | 通过电缆电压变化检测冲突 | 能量检测、载波检测、混合检测 |

### 6.3 轮询访问介质访问控制（令牌传递协议）

- 核心思想：通过“令牌”（特殊控制帧）分配信道，令牌在结点间循环传递，“拿到令牌的结点才能发送数据”；
- 特点：无冲突，适用于负载很高的广播信道；
- 拓扑适配：逻辑上为环形，物理上可为星形。

## 七、3.6 局域网

局域网（LAN）是“地理范围小（如一所学校）、为一个单位所有”的计算机互联网络，特性由**拓扑结构**、**传输介质**、**介质访问控制方式**（最关键）决定。

### 7.1 局域网核心特点

- 较低的时延和误码率；
- 各站为平等关系（非主从）；
- 支持广播和组播；
- 共享较高的总带宽（高数据传输率）。

### 7.2 局域网拓扑与介质访问控制

| 拓扑类型 | 代表技术             | 物理拓扑      | 逻辑拓扑 | 介质访问控制方式 | 传输介质       |
| -------- | -------------------- | ------------- | -------- | ---------------- | -------------- |
| 总线形   | 以太网（IEEE 802.3） | 星形/拓展星形 | 总线形   | CSMA/CD          | 双绞线（主流） |
| 环形     | 令牌环网             | 星形          | 环形     | 令牌传递         | 双绞线         |
| 环形     | FDDI                 | 双环          | 环形     | 令牌传递         | 光纤           |
| 令牌总线 | 令牌总线网           | 总线形        | 环形     | 令牌传递         | 同轴电缆       |

### 7.3 以太网（IEEE 802.3）

以太网是最常用的局域网技术，核心特点：

- 无连接工作方式（尽最大努力交付）；
- 简化通信，差错纠正由高层完成；
- 支持多种传输介质（同轴电缆、双绞线、光纤）。

#### （1）以太网物理层标准对比

| 类型      | 传输媒体             | 编码方式     | 拓扑结构 | 最大段长 | 最多结点数目 |
| --------- | -------------------- | ------------ | -------- | -------- | ------------ |
| 10BASE5   | 基带同轴电缆（粗缆） | 曼彻斯特编码 | 总线形   | 500m     | 100          |
| 10BASE2   | 基带同轴电缆（细缆） | 曼彻斯特编码 | 总线形   | 185m     | 340          |
| 10BASE-T  | 非屏蔽双绞线（UTP）  | 曼彻斯特编码 | 星形     | 100m     | 2            |
| 10BASE-FL | 光纤对（850nm）      | 曼彻斯特编码 | 点对点   | 2000m    | 2            |

#### （2）以太网MAC帧结构

| 字段          | 长度           | 作用                                    |
| ------------- | -------------- | --------------------------------------- |
| 地址          | 6字节（48bit） | 目的地址和源地址，标识收发结点          |
| 类型          | 2字节          | 指出数据域应交给哪个网络层协议实体处理  |
| 数据          | 46~1500字节    | 包含高层协议消息，不足46字节时需填充    |
| 填充          | 0~46字节       | 确保帧长不小于64字节（CSMA/CD算法要求） |
| 校验码（FCS） | 4字节          | 采用CRC循环冗余码，检测帧传输错误       |

#### （3）高速以太网

- 100BASE-T以太网：双绞线上传输100Mb/s基带信号，星形拓扑，支持全双工/半双工（半双工用CSMA/CD）；
- 吉比特以太网（1Gb/s）：支持全双工/半双工（半双工用CSMA/CD），兼容传统以太网；
- 10吉比特以太网（10Gb/s）：仅使用光纤，工作在全双工方式，无争用问题，不使用CSMA/CD。

### 7.4 无线局域网（IEEE 802.11）

- 标准系列：包括802.11a、802.11b、802.11g、802.11n等；
- 最小构件：基本服务集（BSS），分为两类：
  1. 有固定基础设施：包含1个基站（AP）和若干移动站，跨BSS通信需通过基站；
  2. 无固定基础设施（自组织网络）：移动站平等通信，中间结点具备路由器功能，可独立于因特网运行。

### 7.5 令牌环网

- 组成：各站通过“环接口干线耦合器（TCU）”连接到环上；
- 工作原理：分布式控制，令牌在环中循环，拿到令牌的结点可发送数据；
- 拓扑：物理星形，逻辑环形。

## 八、3.7 广域网

广域网（WAN）是“覆盖范围广（跨区域）”的网络，由“节点交换机”和“连接交换机的链路”组成，核心功能是通过节点交换机的“存储转发”实现远距离数据传输。

### 8.1 广域网与局域网对比

| 对比维度   | 广域网（WAN）              | 局域网（LAN）      |
| ---------- | -------------------------- | ------------------ |
| OSI层次    | 物理层、数据链路层、网络层 | 物理层、数据链路层 |
| 覆盖范围   | 广（跨城市、国家）         | 小（单一场所）     |
| 连接方式   | 点到点连接                 | 多点接入           |
| 核心侧重点 | 数据传输（远距离）         | 资源共享           |

### 8.2 广域网核心协议

#### （1）PPP协议

PPP（点对点协议）是串行线路通信的面向字节协议，基于SLIP协议改进（SLIP仅传IP分组，无寻址、校验等功能）。

- 目的：通过拨号或专线建立点对点连接，发送数据；
- 组成部分：
  1. 链路控制协议（LCP）：建立、配置、测试和管理数据链路；
  2. 网络控制协议（NCP）：为不同网络层协议（如IP、IPX）建立和配置逻辑连接；
- 关键特性：
  - 差错检测（硬件CRC校验），但不提供纠错，无序号和确认（不可靠传输）；
  - 仅支持点对点链路，支持全双工；
  - 两端可运行不同网络层协议，仍用同一PPP通信；
  - 透明传输：同步线路用硬件比特填充，异步线路用字节填充。

#### （2）HDLC协议

HDLC（高级数据链路控制协议）是面向比特的同步链路控制协议，适用于点对点/点对多点链路。

- 核心特点：

  1. 全双工通信，数据链路传输效率高；
  2. 传输控制与处理功能分离，灵活性大；
  3. 所有帧采用CRC校验，信息帧顺序编号，防止漏收/重发（高可靠性）。
- 配置方式与站类型：

  | 配置方式   | 站类型     | 特点                             |
  | ---------- | ---------- | -------------------------------- |
  | 非平衡配置 | 主站、从站 | 主站控制链路，从站按主站命令操作 |
  | 平衡配置   | 复合站     | 两站平等，均可发起数据传输       |
- 数据操作方式：

  1. 常响应方式（非平衡）：主站传数据，从站需主站许可后响应；
  2. 异步响应方式（非平衡）：从站无需许可即可响应；
  3. 异步平衡方式（平衡）：复合站可直接向对方传输数据。
- HDLC帧类型：

  | 帧类型        | 位标识（第1-2位） | 功能                                 |
  | ------------- | ----------------- | ------------------------------------ |
  | 信息帧（I）   | 0x01（0和1）      | 传输数据，捎带确认                   |
  | 监督帧（S）   | 10                | 流量控制、差错控制（确认、请求重发） |
  | 无编号帧（U） | 11                | 链路建立、拆除等控制功能             |

## 九、3.8 数据链路层设备

数据链路层设备主要包括**网桥**和**局域网交换机**，核心功能是“连接不同LAN网段，隔离碰撞域，扩展网络范围”。

### 9.1 网桥

网桥工作在数据链路层的MAC子层，将多个以太网网段连接成一个大以太网，隔离各网段的碰撞域。

#### （1）基本特点

- 存储转发：从源网段接收帧，按目的网段的MAC协议转发；
- 协议转换：可在不同类型LAN（如以太网、令牌环网）间转发帧，必要时进行链路层协议转换；
- 缓冲空间：需足够大的缓冲区，应对不同网段的速率差异。

#### （2）优点与缺点

- 优点：过滤通信量（减少跨网段数据）、扩大物理范围、互联不同LAN、提高可靠性、改善性能；
- 缺点：增加时延、无流量控制功能、仅适用于小网络（用户少、通信量小）、不同MAC子层网段需帧格式转换。

#### （3）网桥类型

- 透明网桥：
  - 工作原理：通过“自学习算法”建立转发表，若“源LAN与目的LAN相同”则丢弃帧，否则转发；
  - 缺点：不选择最佳路由，仅按转发表转发。
- 源路由网桥：
  - 工作原理：路由选择由源站负责，源站发送“发现帧”探测路径，生成最佳路由；目的LAN未知时扩散帧；
  - 缺点：发现帧过多可能导致网络阻塞。

### 9.2 局域网交换机

局域网交换机本质是“多端口网桥”，为每个端口连接的设备提供独立碰撞域，提高网络带宽。

#### （1）核心优点

- 经济划分冲突域，为每个工作站提供更高带宽；
- 对工作站透明，管理开销低；
- 简化节点增加、移动和网络变更操作；
- 支持虚拟局域网（VLAN），隔离冲突域和广播域。

#### （2）工作原理

- 检测端口接收数据帧的源/目的MAC地址，与内部动态查找表对比；
- 若MAC地址不在查找表中，加入表并转发帧到对应目的端口；
- 转发表通过“自学习算法”自动建立。

#### （3）交换模式

| 交换模式   | 工作流程                                      | 优点                           | 缺点                                       |
| ---------- | --------------------------------------------- | ------------------------------ | ------------------------------------------ |
| 直通式     | 仅检查帧的目的地址，立即转发                  | 速度快，延迟小                 | 无差错检测，缺乏安全性，不支持不同速率端口 |
| 存储转发式 | 先缓存整帧，检查CRC（无错则转发，有错则丢弃） | 可靠性高，支持不同速率端口转换 | 延迟较大（需缓存整帧）                     |
