# 第5章 中央处理器

## 一、CPU的组成与核心功能

### 1.1 CPU的组成

- **运算器**：对数据进行加工处理（算术运算、逻辑运算）。
- **控制器**：协调并控制计算机各部件执行程序的指令序列，核心操作包括**取指令、分析指令、执行指令**。

### 1.2 CPU的具体功能

1. **操作控制**：一条指令的功能通常由若干操作信号的组合实现，CPU负责管理这些操作信号。
2. **指令控制**：完成“取指令→分析指令→执行指令”的全流程，即程序的顺序控制。
3. **时间控制**：对各类操作进行时间上的调度，为每条指令按时间顺序提供所需的控制信号。
4. **数据加工**：对数据执行算术运算（如加减乘除）和逻辑运算（如与、或、非）。
5. **中断处理**：应对计算机运行中的异常情况（如硬件故障）和特殊请求（如I/O设备请求）。

## 5.1 CPU的功能和基本结构

### 5.1.1 运算器的组成及功能

运算器是数据加工的核心部件，由以下子模块构成：

- **算术逻辑单元（ALU）**：主要功能是执行算术运算（如加法、乘法）和逻辑运算（如比较、异或）。
- **暂存寄存器**：用于临时存放从主存读取的数据，对应用程序员**透明**（即程序员无法直接操作）。
- **累加寄存器（ACC）**：通用寄存器，暂存ALU的运算结果，也可作为加法运算的一个输入端。
- **通用寄存器组**：存放操作数（源操作数、目的操作数）、中间结果及各类地址信息。
- **程序状态字寄存器（PSW）**：保留算术逻辑运算指令或测试指令产生的状态信息，包括：
  - 溢出标志（OF）
  - 符号标志（SF）
  - 零标志（ZF）
  - 进位标志（CF）
- **移位器**：对操作数或运算结果执行移位运算（如左移、右移、循环移位）。
- **计数器**：控制乘除运算的操作步数。

### 5.1.2 控制器的组成及功能

控制器是指令执行的控制核心，由以下子模块构成：

- **程序计数器（PC）**：指出下一条指令在主存中的存放地址，指令取出后自动递增（PC+1）。
- **指令寄存器（IR）**：保存当前正在执行的指令。
- **指令译码器**：仅对指令的“操作码字段”进行译码，向控制器提供特定的操作信号。
- **存储器地址寄存器（MAR）**：存放待访问的主存单元地址（读/写地址）。
- **存储器数据寄存器（MDR）**：存放向主存写入的信息，或从主存读出的信息。
- **时序系统**：产生各类时序信号（由统一时钟CLOCK分频得到），同步CPU的所有操作。
- **微操作信号发生器**：根据IR的指令内容、PSW的状态信息及时序信号，生成控制整个计算机系统的微操作信号。

## 5.2 指令执行过程

### 5.2.1 核心概念（周期关系）

- **指令周期**：CPU从主存取出一条指令到完成该指令的全部时间（即CPU完成一条指令的总时间）。
- **机器周期**：指令周期的组成单位，一个指令周期包含多个机器周期（如取指周期、执行周期）。
- **时钟周期**：CPU操作的基本时间单位，一个机器周期包含若干个时钟周期。
  （注：不同指令的指令周期包含的机器周期数可不同，同一机器周期包含的时钟周期数也可不同）

### 5.2.2 指令周期的基本组成

1. **取指周期**：从主存中取出当前要执行的指令。
2. **间址周期**：若指令需间接寻址，取出操作数的有效地址（EA）。
3. **执行周期**：取出操作数并执行指令规定的运算（如算术运算、逻辑运算）。
4. **中断周期**：若存在中断请求，保存当前程序断点（PC值），并跳转至中断服务程序。

### 5.2.3 不同指令的指令周期

- **无条件转移指令**：无需访问主存获取操作数，仅包含“取指周期+执行周期”。
- **含中断的指令**：当CPU采用中断方式实现主机与I/O设备交换时，CPU在每条指令执行结束前会查询中断请求，因此需包含“中断周期”。

### 5.2.4 指令周期的数据流

#### 1. 取指周期

1. 控制器（CU）发出读命令→控制总线→主存；
2. 程序计数器（PC）的内容（指令地址）→存储器地址寄存器（MAR）→地址总线→主存；
3. 主存根据地址读出指令→数据总线→存储器数据寄存器（MDR）；
4. MDR中的指令→指令寄存器（IR）；
5. PC内容自动加1（PC+1），指向 next 指令地址。

#### 2. 间址周期

1. 指令寄存器（IR）中的地址码（或MDR中的地址）→MAR→地址总线→主存；
2. CU发出读命令→控制总线→主存；
3. 主存读出有效地址→数据总线→MDR（暂存有效地址）。

#### 3. 执行周期

根据IR中的指令类型（如加法、移位）和ALU的运算需求，产生执行结果，不同指令的执行流程差异较大（如加法需取操作数并运算，移位直接操作寄存器数据）。

#### 4. 中断周期

1. 栈指针（SP）减1（SP--）→MAR→地址总线→主存；
2. CU发出写命令→控制总线→主存；
3. 程序计数器（PC）的断点地址→MDR→数据总线→主存（保存断点）；
4. 中断服务程序的入口地址→PC（跳转至中断服务程序）。

### 5.2.5 指令执行方案

| 执行方案       | 核心特点                                                                         | 优缺点                                                           |
| -------------- | -------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 单指令周期     | 所有指令的完成时间相同，指令串行执行；指令周期取决于**最长指令的执行时间** | 优点：控制简单；缺点：系统整体运行速度低                         |
| 多指令周期     | 指令串行执行，为不同指令分配不同的机器周期（如简单指令少分配周期）               | 优点：比单指令周期高效；缺点：仍为串行执行，效率有限             |
| 流水线（并行） | 将每个时钟周期充分利用，指令并行运行（CISC可优化实现，RISC必须实现）             | 优点：大幅提升执行效率；缺点：需解决冲突（如资源冲突、数据冲突） |

## 5.3 数据通路的功能和基本结构

### 5.3.1 数据通路的核心概念

- **定义**：数据在CPU功能部件（如寄存器、ALU）之间传送的路径。
- **功能**：实现CPU内部运算器与寄存器之间的数据交换，以及CPU与主存、I/O设备之间的数据传送。

### 5.3.2 数据通路的基本结构分类

#### 1. CPU内部单总线方式

- **结构**：所有寄存器的输入/输出端连接在同一条公共总线上。
- **关键说明**：
  - ALU无内部存储功能，运算时需确保操作数在ALU两端同时有效；
  - 主存与CPU、寄存器之间的数据传送均通过该总线完成。
- **优缺点**：优点是结构简单；缺点是存在总线冲突（同一时间只能传一组数据），性能低。

#### 2. 专用数据通路方式

- **结构**：减少共享线路，为特定数据传送路径设置专用线路（如ALU与ACC之间的专用通路）。
- **优缺点**：优点是执行效率高（无冲突）；缺点是实现复杂，硬件需求量大。

#### 3. CPU内部三总线方式

- **结构**：将所有寄存器的输入/输出端连接在**多条公共通路**上（通常为3条）。
- **优缺点**：优点是性能高于单总线（减少冲突）；缺点是实现复杂度介于单总线与专用通路之间。

### 5.3.3 数据通路的外部连接

- **运算器**：通过数据总线与内存储器、输入设备、输出设备传送数据。
- **输入/输出设备**：通过接口电路与总线连接（无法直接连总线）。
- **总线分工**：
  - 地址总线：内存储器、I/O设备接收地址信息；
  - 控制总线：传递控制信号（如读/写命令）；
  - 数据总线：内存储器、I/O设备与其他部件传送数据。

## 5.4 控制器的功能和工作原理

### 5.4.1 控制器的核心功能

1. 从主存中取出指令，并产生下一条指令的主存地址（更新PC）；
2. 对指令的操作码进行译码或测试，生成相应的操作控制信号；
3. 指挥并控制CPU、主存、I/O设备之间的数据流动方向；
4. 根据指令要求、时序信号及内部/外部状态，按时间顺序发送微操作控制信号。

### 5.4.2 控制器的分类（按微操作信号产生方式）

#### （上）硬布线控制器（组合逻辑控制器）

##### 1. 控制单元（CU）的信号来源

- 指令译码器产生的操作码信号；
- 时序系统产生的机器周期信号和节拍信号；
- 执行单元（如ALU）的反馈标志（如PSW中的OF、CF）；
- 系统总线的外部信号（如中断请求、DMA请求）。

##### 2. 硬布线控制器的时序系统及微操作

- **时钟周期**：由时钟信号控制节拍发生器，每个节拍内可完成1~n个并行操作。
- **机器周期**：指令执行的基准时间，通常以“主存取指周期”为基准（存储字长=指令字长时）；包含取指周期、间址周期、执行周期、中断周期。
- **指令周期**：见5.2.1节（即完成一条指令的总时间）。

##### 3. CPU控制方式

| 控制方式 | 核心特点                                                                | 优缺点                                                       |
| -------- | ----------------------------------------------------------------------- | ------------------------------------------------------------ |
| 同步控制 | 采用统一时钟信号同步所有部件，微操作命令按固定时序发送                  | 优点：控制电路简单；缺点：需按最慢部件的速度设计，整体效率低 |
| 异步控制 | 无基准时标信号，每个部件按自身速度工作，通过“握手信号”协调            | 优点：速度快（按需工作）；缺点：控制电路复杂                 |
| 联合控制 | 同步与异步结合：大部分部件同步（如取指、执行），小部分异步（如I/O操作） | 优点：兼顾效率与复杂度；缺点：设计难度高于纯同步             |

##### 4. 硬布线控制器设计步骤

1. 列出微操作命令时间表（按机器周期、节拍梳理每个步骤的微操作）；
2. 对微操作信号进行逻辑综合（将时间表转化为逻辑表达式）；
3. 画出微操作命令的逻辑电路图（实现逻辑表达式）。

#### （下）微程序控制器

##### 1. 基本概念

- **微命令**：控制部件向执行部件发出的最小控制命令（如“PC→MAR”“读主存”），是构成控制序列的基本单位。
- **微操作**：微命令对应的执行部件动作（如“PC内容送入MAR”是“PC→MAR”微命令的微操作）。
- **微命令的相容性**：
  - 相容微命令：可同时执行的微命令（如“PC→MAR”与“读命令”）；
  - 相斥微命令：不可同时执行的微命令（如“读命令”与“写命令”）。
- **微程序**：实现一条机器指令功能的微命令序列（一条机器指令对应一段微程序）。
- **控制存储器（CM）**：存放微程序的ROM（只读，避免微程序被篡改）；主存储器（RAM）存放用户程序和数据，二者独立。

##### 2. 微程序控制器的基本组成

- **微地址寄存器（CMAR）**：存放控制存储器（CM）的读/写地址（即微指令地址）。
- **微指令寄存器（CMDR/uIR）**：存放从CM中读出的当前微指令。
- **控制存储器（CM）**：存放微程序（ROM构成）。
- **微地址形成部件**：产生初始微地址（如指令操作码对应的微程序入口）和后继微地址（如当前微指令的下地址字段）。

##### 3. 微程序控制器的工作过程

1. **取微程序入口地址**：机器指令的操作码通过微地址形成部件，生成对应微程序的入口地址→送入CMAR。
2. **取微指令**：从CM中读出入口地址对应的微指令→送入CMDR。
3. **执行微指令**：CMDR中的微操作控制字段生成控制信号，驱动执行部件完成微操作；同时，顺序控制字段或微地址形成部件生成下一条微指令的地址→送入CMAR。
4. **循环执行**：重复步骤2~3，直至执行完当前机器指令对应的所有微指令，再回到步骤1处理下一条机器指令。

##### 4. 微指令编码方式

| 编码方式       | 核心特点                                                         | 优缺点                                                               |
| -------------- | ---------------------------------------------------------------- | -------------------------------------------------------------------- |
| 直接编码法     | 微指令的操作控制字段每一位对应一个微命令（1表示有效，0表示无效） | 优点：无需译码，速度快，并行性好；缺点：微指令字长过长，CM容量需求大 |
| 字段直接编码法 | 将操作控制字段分为若干段，每段对应一组相斥微命令（段内译码）     | 优点：缩短微指令字长；缺点：需增加译码电路，速度略慢                 |
| 字段间接编码法 | 一个字段的微命令由另一个字段的微命令解释（辅助编码）             | 优点：进一步缩短字长；缺点：削弱并行控制能力，仅作为辅助手段         |

##### 5. 微指令地址形成方式

- 直接由微指令的“下地址字段”给出（简单直接）；
- 根据机器指令的操作码形成（微程序入口地址）；
- 根据PSW的状态标志形成（如条件转移微指令的地址）。

##### 6. 微指令格式分类

| 格式类型     | 核心特点                                                             | 优缺点                                                                         |
| ------------ | -------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 水平型微指令 | 一条微指令包含多个并行的微命令，直接控制部件操作                     | 优点：微程序短（并行度高），执行速度快，灵活性高；缺点：微指令字长，编写难度大 |
| 垂直型微指令 | 一条微指令仅包含一个微命令，类似机器指令的格式（如“取数”“加法”） | 优点：微指令字短，简单规整，编写易；缺点：微程序长（串行执行），速度慢         |
| 混合型微指令 | 结合水平型与垂直型特点，平衡字长与并行度                             | 优点：兼顾效率与易用性；缺点：设计需权衡二者，无绝对优势                       |

##### 7. 动态微程序设计与毫微程序设计

- **动态微程序设计**：通过EPROM（可擦除ROM）存放微程序，允许用户根据需求修改或更新微程序（如扩展指令集）。
- **毫微程序设计**：在微程序控制器基础上增加“毫微程序存储器”，将微命令进一步分解为“毫微命令”，由毫微程序解释执行微指令（适用于复杂系统）。

##### 8. 硬布线控制器与微程序控制器的对比

| 对比维度 | 硬布线控制器                     | 微程序控制器                     |
| -------- | -------------------------------- | -------------------------------- |
| 核心实现 | 组合逻辑电路（如与门、或门）     | 存储逻辑（ROM+寄存器）           |
| 速度     | 快（无译码延迟）                 | 慢（需读CM、译码）               |
| 灵活性   | 差（修改指令需重新设计逻辑电路） | 好（修改微程序即可，无需改硬件） |
| 维护性   | 差（逻辑电路复杂，难调试）       | 好（微程序规整，易调试）         |
| 适用场景 | RISC CPU（指令集简单，需高速）   | CISC CPU（指令集复杂，需灵活）   |

## 5.5 指令流水线

### 5.5.1 流水线的核心概念（上）

- **定义**：将指令执行的重复过程分解为若干个子过程（如取指、分析、执行），每个子过程由独立部件处理，不同指令的子过程可并行执行。
- **核心优点**：仅增加少量硬件，即可将计算机运算速度提高数倍（充分利用部件并行性）。

### 5.5.2 指令执行的基本阶段

1. **取指（IF）**：根据PC从主存取出指令→送入IR；PC自动加1。
2. **分析（ID）**：对IR中的操作码译码，按寻址方式形成有效地址（EA），从EA取出操作数→送入通用寄存器。
3. **执行（EX）**：根据操作码完成规定功能（如ALU运算），将结果写入通用寄存器或主存。

### 5.5.3 多条指令的处理方式

#### 1. 顺序执行方式（传统冯·诺依曼机）

- **流程**：一条指令执行完后，再执行下一条（IF1→ID1→EX1→IF2→ID2→EX2→…）。
- **时间计算**：处理n条指令的总时间T=3n×t（t为单个阶段的时间）。
- **优缺点**：优点是控制简单，硬件代价小；缺点是部件利用率低（如ALU仅在EX阶段工作），执行速度慢。

#### 2. 一次重叠执行方式

- **流程**：第k条指令的EX阶段与第k+1条指令的IF阶段并行（IF1→ID1→EX1，IF2→ID2→EX2；EX1与IF2重叠）。
- **时间计算**：处理n条指令的总时间T=(n+2)×t。
- **优缺点**：优点是程序执行时间缩短1/3，部件利用率提高；缺点是硬件开销增加（需增加缓冲寄存器），控制复杂。

#### 3. 二次重叠执行方式

- **流程**：第k条指令的EX阶段与第k+1条指令的ID阶段、第k+2条指令的IF阶段并行（IF1→ID1→EX1，IF2→ID2→EX2，IF3→ID3→EX3；EX1与ID2、IF3重叠）。
- **优缺点**：优点是时间更短（T=(n+1)×t），利用率更高；缺点是硬件开销更大（需更多缓冲），控制更复杂（需解决冲突）。

### 5.5.4 流水线的特点

1. 流水线需“流动”：若频繁断流（如冲突），则无法体现并行优势。
2. 每个功能段后需设置**锁存器**：保存本流水段的结果，避免影响下一段。
3. 功能段时间需尽量相等：若某段时间过长（如EX段比IF段长），会导致后续段等待（“瓶颈”），引发断流。
4. 需“装入时间”与“排空时间”：
   - 装入时间：第一个任务进入流水线到第一个任务输出的时间（如3t，IF+ID+EX）；
   - 排空时间：最后一个任务进入流水线到最后一个任务输出的时间（如2t，ID+EX）。

### 5.5.5 流水线的分类

#### 1. 按流水级别分类

- **部件功能级流水线**：将复杂运算（如乘法）分解为子过程（如部分积相加、移位），组成流水线（如ALU流水线）。
- **处理机级流水线**：将一条指令的解释过程分解为子过程（IF、ID、EX），组成流水线（即指令流水线）。
- **处理机间流水线（宏流水）**：多个处理机串联，每个处理机完成一个任务（如处理机1做IF，处理机2做ID），结果存于共享存储器。

#### 2. 按功能分类

- **单功能流水线**：仅能完成单一功能（如仅做加法运算的流水线）。
- **多功能流水线**：通过调整功能段的连接方式，实现多种功能（如既能做加法，也能做乘法）。

#### 3. 按连接方式分类

- **静态流水线**：同一时间内，所有功能段仅按一种功能的连接方式工作（如某时刻仅做加法，不能同时做乘法）。
- **动态流水线**：同一时间内，不同功能段可按不同功能连接（如段1-2做加法，段3-4做乘法），效率高但控制复杂。

#### 4. 按是否有反馈信号分类

- **线性流水线**：无反馈回路，任务单向流动（如IF→ID→EX→WB），结构简单。
- **非线性流水线**：存在反馈回路（如乘法流水线中部分积需反馈回ALU再次运算），适合线性递归运算（如阶乘）。

### 5.5.6 影响流水线的因素及解决方法（下）

#### 1. 结构相关（资源冲突）

- **定义**：同一时刻，多条指令争抢同一资源（如主存、总线）。
- **解决方法**：
  - 在冲突指令之间插入暂停周期（stall），等待资源释放；
  - 单独设置指令存储器（I-MEM）和数据存储器（D-MEM），分离指令与数据的访问路径（避免取指与取数冲突）。

#### 2. 数据相关（数据冲突）

- **定义**：一条指令的执行依赖前一条指令的运算结果（如指令2需用指令1的结果，但若指令2先执行则出错）。
- **解决方法**：
  - 硬件阻塞（stall）：检测到冲突后，暂停后续指令，等待结果生成；
  - 软件插入NOP指令：编译器在冲突指令间插入空操作（NOP），预留结果生成时间；
  - 数据旁路（Forwarding）：将前一条指令的结果直接送到后一条指令的ALU输入端（无需等写入寄存器）。

#### 3. 控制相关（控制冲突）

- **定义**：转移指令（如JMP、Branch）或改变PC的指令导致流水线断流（无法确定下一条指令的地址）。
- **解决方法**：
  - 分支预测：提前猜测转移方向（如静态预测“总是不转移”，动态预测根据历史结果调整）；
  - 预取双路径：同时预取“转移成功”和“转移失败”两条路径的指令，冲突后丢弃无用指令；
  - 加快条件码生成：在EX阶段提前计算条件码（如是否为零），缩短转移判断时间；
  - 延迟转移：将转移指令后的一条无关指令“移动”到转移延迟槽，避免断流。

### 5.5.7 流水线的性能指标

#### 1. 吞吐率（TP）

- **定义**：单位时间内流水线完成的任务（指令）数量。
- **计算公式**：TP = n / Tk（n为任务数，Tk为处理n个任务的总时间）。
- **最大吞吐率（TPmax）**：当n→∞时，TPmax = 1 / t（t为单个流水段的时间，假设各段时间相等）。

#### 2. 加速比（S）

- **定义**：不使用流水线（顺序执行）的时间与使用流水线的时间的比值。
- **计算公式**：S = T顺 / T流（T顺为顺序执行时间，T流为流水线执行时间）。
- **最大加速比（Smax）**：当n→∞时，Smax = k（k为流水段数，假设各段时间相等）。

#### 3. 效率（η）

- **定义**：流水线的有效工作时间与总工作时间的比值（反映流水线的资源利用率）。
- **计算公式**：η = （n个任务的有效时空区面积） / （k个流水段的总时空区面积）= T流 / (k×Tk)（k为流水段数）。
- **最大效率（ηmax）**：当n→∞时，ηmax = 1（资源完全利用）。

### 5.5.8 先进流水线技术

#### 1. 超标量流水线技术

- **核心**：每个时钟周期内并发执行多条独立指令（如每个周期执行2条指令）。
- **实现条件**：
  - 硬件：设置多个ALU、寄存器组（如双发射、四发射结构）；
  - 软件：编译器优化，将可并行执行的指令“搭配”成指令组，挖掘指令级并行性（ILP）。

#### 2. 超流水线技术

- **核心**：在一个时钟周期内将流水段进一步细分（如将原来1个时钟周期的IF段分为IF1、IF2两个子段），使一个功能部件在一个时钟周期内被使用多次（如每个时钟周期完成2次取指）。
- **关键**：需编译器优化指令调度，避免子段冲突；本质是“时间上的并行”（细分周期）。

#### 3. 超长指令字（VLIW）技术

- **核心**：编译器将多条可并行执行的指令“打包”成一条超长指令（如64位或128位），由多个功能部件同时执行指令中的不同操作。
- **特点**：硬件简单（无需动态调度），依赖编译器挖掘ILP；缺点是指令字长过长，灵活性低。

## 指令周期执行模板

### 1. 取指令周期（所有指令通用）

1. PC → MAR（将下一条指令的地址送入MAR）；
2. 1 → R（发出主存读命令）；
3. M(MAR) → MDR（从主存读出指令，送入MDR）；
4. MDR → IR（将指令送入IR保存）；
5. OP(IR) → CU（将指令的操作码送入CU，进行译码）；
6. (PC) + 1 → PC（PC自动加1，指向 next 指令）。

### 2. 间址周期（仅间接寻址指令）

1. Ad(IR) → MAR（将指令中的形式地址送入MAR）；
2. 1 → R（发出主存读命令）；
3. M(MAR) → MDR（从主存读出有效地址，送入MDR）。

### 3. 非访存指令（无主存访问）

| 指令类型        | 执行步骤                                                       |
| --------------- | -------------------------------------------------------------- |
| CLA（清ACC）    | 0 → ACC（将累加寄存器ACC清零）                                |
| COM（取反）     | $\overline{ACC}$ → ACC（将ACC中的内容按位取反后送回ACC）    |
| SHR（算术右移） | L(ACC) ← R(ACC)，ACC → ACC（ACC内容算术右移1位，符号位不变） |
| CSL（循环左移） | R(ACC) ← L(ACC)，ACC → ACC（ACC内容循环左移1位）             |
| STP（停机）     | 0 → G（设置停机标志G为0，CPU停止工作）                        |

### 4. 访存指令（需访问主存）

#### （1）ADDX（加法指令）

1. Ad(IR) → MAR（将操作数地址送入MAR）；
2. 1 → R（发出读命令）；
3. M(MAR) → MDR（从主存读出操作数，送入MDR）；
4. (ACC) + (MDR) → ACC（ACC与MDR中的数相加，结果送回ACC）。

#### （2）STAX（存数指令）

1. Ad(IR) → MAR（将目标地址送入MAR）；
2. ACC → MDR（将ACC中的数据送入MDR）；
3. 1 → W（发出写命令）；
4. MDR → M(MAR)（将MDR中的数据写入主存目标地址）。

#### （3）LDAX（取数指令）

1. Ad(IR) → MAR（将操作数地址送入MAR）；
2. 1 → R（发出读命令）；
3. M(MAR) → MDR（从主存读出操作数，送入MDR）；
4. MDR → ACC（将操作数送入ACC）。

### 5. 转移指令

#### （1）JMPX（无条件转移）

Ad(IR) → PC（将指令中的目标地址直接送入PC，跳转至目标地址）。

#### （2）BANX（条件转移：负则转）

若PSW中的符号标志SF=1（结果为负），则 Ad(IR) → PC（跳转至目标地址）；否则PC保持不变（执行下一条指令）。
