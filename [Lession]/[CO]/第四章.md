# 第4章 指令系统

## 4.1 指令格式

### 4.1.1 指令的基本格式（操作码+地址码）

#### 1. 指令结构

- 操作码（OP）：指出指令中应该执行什么性质的操作和具有何种功能。
- 地址码：给出被操作的信息（指令或者数据）的地址。

#### 2. 指令长度

- 单字长指令：长度等于机器字长。
- 双字长指令：长度等于两倍机器字长。
- 半字长指令：长度等于半个机器字长。
- 变长指令字结构：各种指令的长度不同。
- 定长指令字结构：所有指令长度相同。

#### 3. 根据操作数地址码数目分类

| 指令类型   | 格式                          | 指令用途                                                                                             | 其他说明                                                     |
| ---------- | ----------------------------- | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| 零地址指令 | OP（仅操作码）                | 1. 空操作指令、停机指令、关中断指令；`<br>`2. 运算类指令仅使用在堆栈计算机中                       | 无地址码                                                     |
| 一地址指令 | OP A1                         | 1. 只有目的操作数的单操作数指令；`<br>`2. 隐含约定目的地址的双操作数指令（如加1、减1、求反、求补） | A1 为操作数地址                                              |
| 二地址指令 | OP A1 A2                      | 算术和逻辑运算指令，需两个操作数（分别为目的操作数地址A1、源操作数地址A2），A1同时用于保存运算结果   | -                                                            |
| 三地址指令 | OP A1 A2 A3（结果）           | 算术和逻辑运算指令，结果直接存放在A3中                                                               | 需要访问4次存储器（取指令1次、取两个操作数2次、存放结果1次） |
| 四地址指令 | OP A1 A2 A3（结果）A4（下址） | 算术和逻辑运算指令，相较于三地址指令，多了下一条执行指令的地址（A4）                                 | -                                                            |

#### 4. 操作码指令格式

- **定长操作码指令格式**

  - 优点：对于简化计算机硬件设计，提高指令译码和识别速度很有利。
  - 缺点：指令数量增加时会占用更多固定位，留给表示操作数地址的位数受限。
- **扩展操作码指令格式**

  - 实现方式：全部指令的操作码字段位数不固定，分散在指令字的不同位置。
  - 优点：丰富了指令的种类。
  - 缺点：增加了指令译码和分析难度，控制器设计变得复杂。
  - 注意事项：1. 短码不能是长码的前缀；2. 指令操作码不能重复。

## 4.2 指令寻址方式

### 4.2.1 指令寻址和数据寻址

#### 1. 指令寻址

- **顺序寻址**：通过程序计数器（PC）加1，自动生成下一条指令的地址。
- **跳跃寻址**：通过转移类指令实现，是否跳跃受到状态寄存器和操作数的控制。
  - 跳跃到的地址分类：
    - 绝对地址：由标记符直接得到。
    - 相对地址：相对于当前指令地址的偏移量。
  - 跳跃的结果：当前指令修改PC值。

#### 2. 数据寻址

- 定义：在指令中表示一个操作数的地址。
- 结构：操作码 + 寻址特征 + 形式地址A。

### 4.2.2 常见的数据寻址方式

| 寻址方式       | 定义                                                           | 优点                                      | 缺点                                                                                         | 访存次数                       |
| -------------- | -------------------------------------------------------------- | ----------------------------------------- | -------------------------------------------------------------------------------------------- | ------------------------------ |
| 隐含寻址       | 操作数地址隐含在指令或硬件中                                   | 有利于缩短指令字长                        | 增加存储操作数或隐含地址的硬件                                                               | 不访存                         |
| 立即（数）寻址 | 指令字中直接给出操作数（形式地址即操作数）                     | 不需要访问主存，指令执行时间最短          | 位数限制了立即数的范围                                                                       | 不访存                         |
| 直接寻址       | 指令字中的形式地址就是操作数的真实地址                         | 访问一次主存，不需要专门计算操作数的地址  | 形式地址的位数限制了寻址范围，操作数地址不易修改                                             | 访存1次                        |
| 间接寻址       | 指令的地址字段给出的是“存储操作数地址的地址”（类似“套娃”） | 扩大了寻址范围，方便编制程序              | 需要多次访存，访问速度过慢（该寻址方式不常用）；注：一般“扩大寻址范围”通常指寄存器间接寻址 | 访存多次（具体看间接寻址次数） |
| 寄存器寻址     | 指令字中直接给出操作数所在的寄存器编号                         | 不访问主存，执行速度快，支持向量/矩阵运算 | 寄存器价格高昂，寄存器个数有限                                                               | 不访存                         |

## 4.3 CISC和RISC概念

### 1. 基本概念

- 核心区分：基于指令的使用频度，指令系统分为复杂型（CISC）和精简型（RISC）。

### 2. CISC与RISC核心特征对比

| 对比维度       | CISC（复杂指令集计算机）     | RISC（精简指令集计算机）            |
| -------------- | ---------------------------- | ----------------------------------- |
| 指令系统       | 复杂庞大                     | 精简简单                            |
| 指令数目       | 大于200条                    | 小于100条                           |
| 指令字长       | 不固定                       | 定长                                |
| 访存指令       | 不加限制                     | 只有load（取数）和store（存数）指令 |
| 指令执行时间   | 相差较大                     | 绝大多数在一个周期内完成            |
| 通用寄存器数量 | 较少                         | 较多                                |
| 目标代码       | 难以优化编译生成高效目标代码 | 采用优化编译程序，生成代码高效      |
| 控制方式       | 绝大多数采用微程序控制       | 绝大多数采用组合逻辑控制            |
| 指令流水线     | 可以实现                     | 必须实现                            |

### 3. RISC优点

- 采用组合逻辑控制，硬布线使用较少。
- 运算速度更快。
- 设计方便，可靠性高，机器设计周期短，逻辑简单。
- 有利于编译程序代码优化。
