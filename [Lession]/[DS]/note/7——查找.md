# 查找技术知识点梳理

## 7.1 查找的基本概念

### 1. 核心定义

- **查找**：在数据集合中寻找满足某种条件的数据元素的过程。
- **查找表（查找结构）**：用于查找的数据集合，由同一类型的数据元素（或记录）组成，可采用数组、链表等数据类型存储。

### 2. 查找表的操作

1. 查询某个特定的数据元素是否在查找表中；
2. 检索满足条件的某个特定数据元素的各种属性；
3. 在查找表中插入一个数据元素；
4. 从查找表中删除一个数据元素。

### 3. 查找表的分类

| 类型       | 定义                                       |
| ---------- | ------------------------------------------ |
| 静态查找表 | 查找后不会对表进行任何修改的查找表         |
| 动态查找表 | 查找后可能对表进行插入、删除等修改的查找表 |

### 4. 关键字

数据元素中**唯一标识该元素**的某个数据项的值。基于关键字的查找结果具有唯一性（即同一查找表中无重复关键字）。

### 5. 平均查找长度（ASL）

#### （1）定义

- 一次查找的长度：查找过程中需要比较的关键字次数；
- 平均查找长度：所有查找过程中关键字比较次数的平均值，是衡量查找算法效率的**核心指标**。

#### （2）数学表达式

$[ ASL = \sum_{i=1}^{n} P_i \times C_i ]$

#### （3）参数含义

- \( n \)：查找表的长度（数据元素总数）；
- \( P_i \)：查找第\( i \)个数据元素的概率（默认等概率查找，即$( P_i = \frac{1}{n} )$）；
- \( C_i \)：找到第\( i \)个数据元素所需的关键字比较次数。

## 7.2 顺序查找、折半查找与分块查找

### 1. 顺序查找（线性查找）

#### （1）适用场景

主要用于线性表（无序线性表、有序线性表均适用），支持顺序存储和链式存储。

#### （2）基本思想

从线性表的一端（通常是表头）开始，逐个检查元素的关键字是否满足条件：

- 若找到符合条件的元素，返回其位置（查找成功）；
- 若遍历至表尾仍未找到，返回查找失败。

#### （3）性能分析

| 场景     | 平均查找长度（ASL）                            | 特点                                            |
| -------- | ---------------------------------------------- | ----------------------------------------------- |
| 查找成功 | $( ASL_{成功} = \frac{n+1}{2} )$（等概率下） | 对存储结构、元素有序性无要求                    |
| 查找失败 | $( ASL_{失败} = n+1 )$                       | 当\( n \)较大时，效率低（时间复杂度\( O(n) \)） |

### 2. 折半查找（二分查找）

#### （1）适用场景

仅适用于**有序的顺序表**（不支持链式存储，因链式存储无法快速定位中间位置）。

#### （2）基本思想

基于“缩小查找范围”的策略，步骤如下：

1. 取表中间位置的元素，将其关键字与目标值\( key \)比较；
2. 若相等，查找成功，返回中间位置；
3. 若\( key < 中间关键字 \)，则在表的前半部分继续查找；若\( key > 中间关键字 \)，则在表的后半部分继续查找；
4. 重复步骤1-3，直至找到元素（成功）或范围为空（失败）。

#### （3）关键特性

- **判定树**：查找过程可生成一棵平衡二叉树（判定树），圆形结点表示有效记录（关键字），方形结点表示查找失败；
- **树高**：含\( n \)个元素的判定树高$( h = \lceil \log_2(n+1) \rceil )$；
- **时间复杂度**：$( O(\log_2 n) )$（远高于顺序查找）；
- **平均查找长度**：成功时\( ASL_{成功} \)与树高相关，失败时\( ASL_{失败} \)依赖于方形结点的层数。

## 平衡二叉树（AVL树）

#### 1. 定义（回顾）

- 任意节点的左、右子树深度差（平衡因子）的绝对值 ≤ 1；
- 平衡因子 ∈ {-1, 0, 1}；
- 目的：避免二叉排序树退化为单链，保证查找效率稳定在 `O(log₂n)`。

#### 2. 平衡二叉树的插入

- 核心逻辑：插入节点后，若路径上的节点平衡因子绝对值 > 1（失衡），需通过“旋转”调整平衡；
- 失衡节点：插入路径上离插入点最近的平衡因子绝对值 > 1的节点（记为A）；
- 四种旋转调整方式（根据失衡原因分类）：

##### （1）LL平衡旋转（右单旋转）

- 失衡原因：在A的**左孩子（L）的左子树（L）** 插入新节点，A的平衡因子由1增至2；
- 调整步骤：
  1. 设A的左孩子为B，B的右子树为BR；
  2. 将BR作为A的左子树，A作为B的右子树；
  3. 更新B为新的子树根节点，调整A和B的平衡因子为0。

##### （2）RR平衡旋转（左单旋转）

- 失衡原因：在A的**右孩子（R）的右子树（R）** 插入新节点，A的平衡因子由-1减至-2；
- 调整步骤：
  1. 设A的右孩子为B，B的左子树为BL；
  2. 将BL作为A的右子树，A作为B的左子树；
  3. 更新B为新的子树根节点，调整A和B的平衡因子为0。

##### （3）LR平衡旋转（先左后右双旋转）

- 失衡原因：在A的**左孩子（L）的右子树（R）** 插入新节点，A的平衡因子由1增至2；
- 调整步骤：
  1. 先对B（A的左孩子）和C（B的右孩子）执行RR旋转（左单旋转），此时C成为B的父节点，B成为C的左孩子；
  2. 再对A和C执行LL旋转（右单旋转），此时C成为A的父节点，A成为C的右孩子；
  3. 根据插入位置调整A、B、C的平衡因子。

##### （4）RL平衡旋转（先右后左双旋转）

- 失衡原因：在A的**右孩子（R）的左子树（L）** 插入新节点，A的平衡因子由-1减至-2；
- 调整步骤：
  1. 先对B（A的右孩子）和C（B的左孩子）执行LL旋转（右单旋转），此时C成为B的父节点，B成为C的右孩子；
  2. 再对A和C执行RR旋转（左单旋转），此时C成为A的父节点，A成为C的左孩子；
  3. 根据插入位置调整A、B、C的平衡因子。

#### 3. 平衡二叉树的查找

- 逻辑与二叉排序树一致，因树高为 `O(log₂n)`，平均查找长度为 `O(log₂n)`，效率稳定。

## 7.3 B树和B+树（多路平衡查找树）

### 1. B树的基本概念

#### （1）核心定义

B树是一种**多路平衡查找树**，“阶”（常用\( m \)表示）是B树的关键参数——所有结点的孩子个数的最大值。

#### （2）B树的特性（阶为\( m \)）

1. 每个结点至多有\( m \)棵子树，即至多含\( m-1 \)个关键字；
2. 根结点若不是终端结点（叶结点），则至少有2棵子树；
3. 非根结点至少有\( $\lceil \frac{m}{2} \rceil$ \)棵子树，即至少含\( $\lceil \frac{m}{2} \rceil - 1$ \)个关键字；
4. 所有叶结点在同一层次，且不带有效信息（仅作为终端标志）；
5. 结点内关键字**左到右递增有序**，关键字两侧的指针满足：
   - 左指针指向的子树中，所有关键字 < 当前关键字；
   - 右指针指向的子树中，所有关键字 > 当前关键字；
6. 结点的孩子个数 = 关键字个数 + 1。

#### （3）B树的高度（磁盘存取次数）

含\( n \)个关键字、阶为\( m \)的B树，高度\( h \)满足：
\[ $h \geq \log_m(n+1)$ \]
（注：当每个结点关键字个数最少时，B树高度最大）。

#### （4）B树的查找

1. 从根结点开始，在当前结点的有序关键字中查找目标值\( key \)；
2. 若找到，查找成功；若未找到，根据指针进入对应子树继续查找；
3. 若遍历至叶结点（指针为空），则查找失败。

#### （5）B树的插入与删除

| 操作 | 核心逻辑                                                                                                                                                                       |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 插入 | 1. 定位：找到最低层的非叶结点作为插入位置；`<br>`2. 插入：若插入后结点关键字数≤\( m-1 \)，直接完成；否则分裂结点（将结点分为两半，中间关键字上移至父结点）。                |
| 删除 | 1. 直接删除：若删除后结点关键字数≥\( $\lceil \frac{m}{2} \rceil - 1$ \)，直接完成；`<br>`2. 合并/借位：若关键字数不足，向兄弟结点借位或与兄弟结点、父结点中间关键字合并。 |

### 2. B+树的基本概念

#### （1）B+树的特性（阶为\( m \)）

1. 分支结点至多有\( m \)棵子树，非根分支结点至少有( $\lceil \frac{m}{2} \rceil$ \)棵子树；
2. 所有**叶结点含全部关键字及记录指针**，且叶结点按关键字有序链接（支持范围查找）；
3. 非叶结点仅起索引作用，含“子结点最大关键字”和“子结点指针”，不含记录地址；
4. 结点的孩子个数 = 关键字个数。

#### （2）M阶B树与M阶B+树的差异

| 对比维度               | M阶B树                                                  | M阶B+树                                           |
| ---------------------- | ------------------------------------------------------- | ------------------------------------------------- |
| 关键字与记录关联       | 非叶结点含关键字对应的记录地址                          | 仅叶结点含记录地址，非叶结点仅存索引关键字        |
| 子树数与关键字数关系   | 有\( n \)个关键字 → \( n+1 \)棵子树                    | 有\( n \)个关键字 → \( n \)棵子树                |
| 关键字个数范围（非根） | \( $\lceil \frac{m}{2} \rceil - 1 \leq n \leq m-1$ \) | \( $\lceil \frac{m}{2} \rceil \leq n \leq m$ \) |
| 关键字重复性           | 叶结点与非叶结点关键字不重复                            | 非叶结点关键字重复出现在叶结点中                  |

## 7.4 散列表（哈希表）

### 1. 散列表的基本概念

- **散列函数**：将关键字映射到对应地址的函数，记为\( Hash(key) = Addr \)；
- **冲突**：不同关键字通过散列函数映射到同一地址的现象；
- **散列表**：基于散列函数构建的直接访问型数据结构，理想查找时间复杂度为\( O(1) \)。

#### （2）散列函数的构造原则

1. 地址分布均匀：尽可能让关键字等概率映射到地址空间，减少冲突；
2. 定义域完整：覆盖所有需存储的关键字；
3. 计算高效：能快速计算任意关键字的散列地址。

### 2. 散列函数的构造方法

| 方法       | 核心逻辑                                                                         | 特点                                               |
| ---------- | -------------------------------------------------------------------------------- | -------------------------------------------------- |
| 直接定址法 | \( $H(key) = key$ \) 或 \( $H(key) = a \times key + b$ \)（\( a,b \)为常数） | 无冲突，计算简单；适合关键字连续分布，否则浪费空间 |
| 除留余数法 | 取质数\( p \) $p \leq 散列表长m$ ， $H(key) = key \% p$                   | 最常用；关键是选好\( p \)，保证地址均匀            |
| 数字分析法 | 选取关键字中数码分布均匀的若干位作为地址                                         | 适合已知关键字集合，更换关键字需重构函数           |
| 平方取中法 | 取关键字平方值的中间几位作为地址                                                 | 地址分布均匀，适合关键字位数不足的场景             |

### 3. 冲突的处理方法

#### （1）开放定址法

核心思想：冲突时，按规则探测其他地址，公式为\( $H_i = (Hash(key) + d_i) \% m$ \)（\( d_i \)为增量序列，\( m \)为散列表长）。

| 探测方式     | 增量序列\( d_i \)                                       | 优点           | 缺点                             |
| ------------ | ------------------------------------------------------- | -------------- | -------------------------------- |
| 线性探测法   | \( 0,1,2,...,m-1 \)                                     | 实现简单       | 易产生“聚集”（冲突关键字集中） |
| 平方探测法   | \( 0^2,1^2,-1^2,2^2,-2^2,... \)                         | 避免聚集       | 无法探测所有地址（至少探测一半） |
| 再散列法     | \( d_i = Hash_2(key) \)（\( Hash_2 \)为第二个散列函数） | 地址分布更均匀 | 需设计两个散列函数，计算量增加   |
| 伪随机序列法 | \( d_i \)为伪随机数                                     | 灵活           | 依赖随机数质量，可能出现局部聚集 |

#### （2）拉链法（链地址法）

核心思想：将映射到同一地址的“同义词”（冲突关键字）存储在一个线性链表中，链表由散列地址唯一标识。

- 优点：无聚集现象，动态扩容方便；
- 缺点：需额外存储链表指针，空间开销略大。

### 4. 散列表的性能分析

#### （1）查找过程

1. 计算目标关键字的初始地址\( $Addr = Hash(key)$ \)；
2. 检查\( Addr \)位置：无记录则失败；有记录且关键字相等则成功；否则按冲突处理规则计算下一个地址，重复步骤2。

#### （2）影响效率的因素

1. **散列函数**：决定初始地址的均匀性；
2. **冲突处理方法**：影响冲突后的探测效率；
3. **装填因子（$( \alpha )$）**：\( $\alpha = \frac{表中记录数n}{散列表长m}$ \)，\( $\alpha$ \)越大，冲突概率越高，效率越低。

#### （3）衡量指标

平均查找长度（ASL）：成功查找和失败查找的平均关键字比较次数，是评估散列表效率的核心指标。
