## 第四章 文件系统与磁盘管理

### 4.1 文件系统基础（上）

#### 一、基本概念

- **文件**：以计算机硬盘为载体的存储在计算机上的信息集合，文件可以是文本文档、图片、程序等。
- **进程**：系统运行时，计算机以进程为基本单位进行资源的调度和分配；用户输入输出时，以文件为基本单位。
- **操作系统的文件系统**：用于实现文件的权限访问、修改、查询和保存等功能。

#### 二、相关定义

1. **数据项**：文件系统中最低级的数据组织形式，分为两种：
   - 基本数据项：用于描述一个对象的某种属性的一个值。
   - 组合数据项：由多个基本数据项组成。
2. **记录**：一组数据项的集合，用于描述一个对象在某方面的属性。
3. **文件**：创建者所定义的一组相关信息的集合，分为两类：
   - 有结构文件（记录式文件）：由相似的记录组成。
   - 无结构文件（流式文件）：由字符流组成。

#### 三、文件的属性

文件的属性包含以下关键信息，用于标识和管理文件：

- **名称**：文件名称唯一，以容易读取的形式保存。
- **标识符**：文件的唯一标签，通常为数字，是对人不可读的内部名称。
- **类型**：被支持的不同类型的文件系统所使用。
- **位置**：指向设备和设备上文件的指针。
- **大小**：文件当前的大小，包含文件允许的最大值。
- **保护**：对文件进行保护的访问控制信息。
- **时间、日期和用户标识**：文件创建、修改和上次访问的相关信息，用于保护和跟踪文件的使用。

#### 四、文件的基本操作

1. **写文件**：执行系统调用，指明文件名称和写入内容，查找文件位置，为该文件维护一个写位置指针，发生写操作时更新写指针。
2. **读文件**：执行系统调用，指明文件名称和文件位置，搜索目录项，系统维护一个读指针，发生读操作时更新该指针。
3. **文件重定位（文件寻址）**：按某条件搜索目录，将当前文件位置设为定值，且不进行读、写文件操作。
4. **删除文件**：搜索目录，找到文件的目录项并使其变为空项，然后回收目标文件占用的存储空间。
5. **截断文件**：允许文件的所有属性不变，删除文件内容（将长度设为0）并释放其空间。
6. **文件的打开与关闭**：
   - **打开（open请求）**：
     1. 首次使用文件时，调用open请求，指明文件的属性（包括物理位置），将其从外存复制到内存打开文件表的一个表目中。
     2. open操作根据文件名搜索目录，将目录条目复制到打开文件表；若请求（创建、只读、读写、添加等）得到允许，进程可打开文件，open返回一个指向打开文件表中条目的指针。
     3. 通过该指针进行I/O操作，可简化步骤并节省资源。
   - **关闭文件**：当文件打开计数（用于记录访问该文件的进程数）为0时，关闭文件并删除打开文件表中的对应条目，避免表内空间不足。

#### 五、文件关联信息

- **文件指针**：系统以上次的读写位置作为当前文件位置的指针，该指针对打开文件的某个进程是唯一的，需与磁盘文件属性分开保存。
- **文件打开计数**：文件关闭时需重用其打开文件表条目，计数器为0时关闭文件并删除条目。
- **文件磁盘位置**：该信息存储在内存中，避免每个操作都从磁盘读取。
- **访问权限**：每个进程打开文件需指定访问模式（创建、只读、读写、添加等），该信息保存在进程打开的文件表中，供操作系统判断是否允许后续I/O请求。

#### 六、文件的逻辑结构

文件的逻辑结构分为无结构文件和有结构文件（记录式文件）两类，具体如下：

| 类型                     | 细分类型          | 特点                                                                         | 优缺点                                                                                                                                                                          |
| ------------------------ | ----------------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 无结构文件               | 字符流文件        | 将数据按顺序组织记录并积累保存，无结构，采用字符流形式                       | 优点：管理简单，方便用户操作；缺点：仅适合基本信息单位操作不多的文件，需穷举搜索                                                                                                |
| 有结构文件（记录式文件） | 顺序文件          | 记录一个接一个排列，记录通常为定长，可顺序存储或链表存储                     | 优点：批量处理时效率最高；缺点：增删改查操作困难`<br>`- 定长记录：按公式A=...可直接获取文件地址；`<br>`- 变长记录：需查找前i-1条记录才能找到第i条，建立索引表可提高查找速度 |
|                          | 索引文件          | 结合顺序和索引两种组织形式，为文件建立索引表，索引项包含记录关键字和物理地址 | 优点：提高查找速度；缺点：索引表占用存储空间                                                                                                                                    |
|                          | 索引顺序文件      | 将顺序文件的所有记录分组，为每组第一条记录建立索引项（含关键字和指针）       | 优点：比顺序文件查找效率高；缺点：索引表占用存储空间                                                                                                                            |
|                          | 直接文件/散列文件 | 通过记录的键值或散列函数转换的键值直接决定物理地址，无顺序特性               | 优点：查找速度快；缺点：无顺序，不适用于需按顺序访问的场景                                                                                                                      |

### 4.1 文件系统基础（中）

#### 一、文件控制块（FCB）与索引结点

1. **文件控制块（FCB）**：

   - 定义：用于存放控制文件所需各种信息的数据结构，实现“按名存取”，包含文件的属性、位置、所有权等信息。
   - 包含信息：
     - 基本信息：文件名、文件的物理位置、逻辑结构、物理结构等。
     - 存取控制信息：文件存取权限。
     - 使用信息：文件建立时间、修改时间。
2. **索引结点**：

   - 定义：检索目录文件时，无需将文件调入内存，仅查找目录项；文件的描述信息单独形成索引结点的数据结构，分为磁盘索引结点和内存索引结点。
   - **磁盘索引结点**：包含以下信息：
     - 文件主标识符：拥有该文件的个人或小组的标识符。
     - 文件类型：普通文件、目录文件、特别文件。
     - 文件存取权限：各类用户对该文件的存取权限。
     - 文件物理地址：含13个地址项，以直接或间接方式给出数据文件所在盘块的编号。
     - 文件长度：以字节为单位。
     - 文件链接计数：文件系统中所有指向该文件的文件名指针计数。
     - 文件存取时间：文件最近被存取、修改的时间，以及索引结点最近被修改的时间。
   - **文件打开后内存索引节点增加的内容**：
     - 索引结点编号：用于标识内存索引节点。
     - 状态：指示i节点是否被上锁或修改。
     - 访问计数：每当有进程访问此结点时计数加1，访问结束减1。
     - 逻辑设备号：文件所属文件系统的逻辑设备号。
     - 链接指针：分别指向空闲链表和散列队列的指针。

#### 二、目录结构

##### （一）目录的基本操作

- 搜索：用户使用文件时，搜索目录找到对应目录项。
- 创建文件：在目录中增加新目录项，记录文件名、位置等信息。
- 删除文件：在目录中删除对应目录项。
- 显示目录：用户请求显示目录内容，展示目录中的所有文件及属性。
- 修改目录：文件属性（如权限、大小）变化时，修改对应目录项。

##### （二）目录结构分类

| 结构类型                     | 特点                                                                                          | 优缺点                                                                                                             |
| ---------------------------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| 单机目录结构                 | 整个文件系统仅建立一张目录表，每个文件占一个目录项                                            | 优点：实现按名存取；缺点：查找速度慢，文件不允许重名，不利于共享，不适用于多用户系统                               |
| 两级目录结构                 | 分主目录和用户目录；主目录记录用户名及用户文件目录的存储位置，用户目录记录该用户文件的FCB信息 | 优点：解决不同用户文件重名问题，一定程度保证文件安全；缺点：缺乏灵活性，不能对文件分类                             |
| 多级目录结构（树形目录结构） | 推广两级目录的层次关系，进程对文件的访问相对于当前目录进行                                    | 优点：有效分类文件，结构层次清晰，便于管理和保护；缺点：按路径名访问需经过中间结点，增加磁盘访问次数，降低查询速度 |
| 无环图目录结构               | 在树形目录结构基础上增加指向同一结点的有向边，形成有向无环图                                  | 优点：有利于实现文件共享；缺点：结构较复杂，需避免循环引用                                                         |

#### 三、文件共享

文件共享主要有两种实现方式：硬链接（基于索引节点）和软链接（符号链），具体对比如下：

| 共享方式               | 实现原理                                                                                                     | 优缺点                                                                                                                                           |
| ---------------------- | ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 硬链接（基于索引节点） | 文件目录中仅设置文件名及指向对应索引节点的指针；索引节点中用“链计数count”记录链接到该节点的用户目录项数目  | 优点：查找速度比软链接快；`<br>`优点：多个指针指向一个索引结点，只要有一个指针存在，索引节点就不会被删除                                       |
| 软链接（符号链）       | 用户B共享用户A的文件F时，系统创建LINK类型的新文件（取名F），存入用户B的目录，新文件仅包含被链接文件F的路径名 | 优点：支持网络共享（仅需提供文件所在机器的网络地址及文件路径）；`<br>`缺点：按路径查找增加时间开销和磁盘启动频率，符号链的索引节点占用硬盘空间 |

### 4.1 文件系统基础（下）

#### 一、文件保护

文件保护的核心是防止文件被破坏或未经允许修改，控制用户对文件的读、写、执行等操作，主要包括访问类型和实现方式。

##### （一）访问类型

- 基础访问类型：读、写、执行、添加、删除、列表清单（列出文件名和属性名）。
- 扩展控制：对文件重命名、复制、编辑等操作的控制。

##### （二）实现方式

| 实现方式 | 原理                                                                                                   | 优缺点                                                                                               |
| -------- | ------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------- |
| 口令保护 | 用户请求访问时需提供对应口令，口令存储在系统中                                                         | 优点：时间和空间开销少；缺点：口令直接存储在系统内部不安全，无法控制访问类型                         |
| 加密保护 | 用户对文件加密，访问时需密钥解密                                                                       | 优点：保密性强，节省存储空间；缺点：加密和解密需花费时间，无法控制访问类型                           |
| 访问控制 | 为每个文件和目录增加访问控制列表，规定每个用户名及允许的访问类型；用户分为“拥有者”“组”“其他”三类 | 优点：可使用复杂的访问方法，精准控制访问权限；缺点：访问控制列表长度无法预计，可能导致复杂的空间管理 |

#### 二、文件层结构

文件系统从上层到下层分为以下模块，各模块功能如下：

1. **用户调用接口**：为用户提供与文件及目录有关的系统调用。
2. **文件目录系统**：管理文件目录、活跃文件目录表、读写状态信息表、用户进程的打开文件表，组织存储设备上的文件目录结构，调用下一级存取控制块。
3. **存取控制验证**：实现文件保护，将用户的访问请求与FCB中的访问控制权限比较，确认访问合法性。
4. **逻辑文件系统与文件信息缓冲区**：根据文件的逻辑结构，将用户要读写的逻辑记录转换为文件逻辑结构内的相应块号。
5. **物理文件系统**：将逻辑记录所在的相对块号转换为实际的物理地址。
6. **辅助分配模块**：管理辅存空间，负责分配和回收辅存空闲空间。
7. **设备管理程序模块**：分配设备及设备读写缓冲区，进行磁盘调度，启动设备，处理设备中断，释放缓冲区和设备。

#### 三、目录实现

目录实现主要有两种方式：

1. **线性列表**：
   - 原理：使用存储文件名和数据块指针的线性表。
   - 优点：实现简单；缺点：查找耗费时间（需遍历列表）。
2. **哈希表**：
   - 原理：根据文件名计算哈希值，返回指向线性列表中对应元素的指针。
   - 优点：查找迅速，插入和删除简单；缺点：需避免哈希冲突，哈希表长度固定，哈希函数依赖表长。

### 4.2 文件系统的实现

#### 一、文件的分配方式

文件的分配方式决定了文件在磁盘上的存储位置，影响存取效率和空间利用率，具体如下：

| 分配方式     | 细分类型 | 原理                                                                                           | 访存次数       | 优缺点                                                                                     |
| ------------ | -------- | ---------------------------------------------------------------------------------------------- | -------------- | ------------------------------------------------------------------------------------------ |
| 连续分配     | -        | 每个文件在磁盘上占有一组连续的块，磁盘地址定义线性排序                                         | 1次            | 优点：实现简单，存取速度快，寻道数和寻道时间最小；缺点：文件长度不宜动态增加，产生外部碎片 |
| 链接分配     | 隐式链接 | 磁盘块分布在磁盘任意位置，除最后一个盘块，其他盘块含指向下一个盘块的指针                       | n次            | 优点：无碎片，外存利用率高；缺点：不能直接访问，稳定性差                                   |
|              | 显示链接 | 将链接文件各物理块的指针提取出来，显式存放在内存的“文件分配表（FAT）”中（整个磁盘设一张FAT） | 减少访问次数   | 优点：显著提高检索速度，减少磁盘访问次数；缺点：文件分配表占用存储空间                     |
| 索引分配     | -        | 为每个文件建立索引块（含该文件所有物理块的地址），解决链接分配不能直接访问的问题               | m级索引需m+1次 | 优点：支持直接访问，无碎片；缺点：索引块占用存储空间                                       |
| 索引分配优化 | 链接方案 | 将多个索引块链接起来，处理大文件                                                               | -              | 优点：支持大文件；缺点：多级链接可能增加访存次数                                           |
|              | 多层索引 | 第一层索引块指向第二层索引块，第二层指向文件块（如两级索引、三级索引）                         | 2级索引需3次   | 优点：支持超大文件；缺点：访存次数随索引层级增加                                           |
|              | 混合索引 | 结合直接地址、单级索引、两级索引等方式（如UNIX系统）                                           | -              | 优点：兼顾小文件（直接地址）和大文件（多级索引）的存取效率                                 |

#### 二、文件存储空间管理

文件存储设备管理的核心是对空闲块的组织、分配与回收，主要方法如下：

1. **空闲表法**：
   - 类型：连续分配方式。
   - 原理：系统为空闲区建立“空闲盘块表”，记录每个空闲区的第一个盘块号、空闲盘块数等信息。
2. **空闲链表法**：
   - 原理：将所有空闲盘区连成一条空闲链，按基本元素不同分为两类：
     - 空闲盘块链：以盘块为单位连成链。
     - 空闲盘区链：以盘区（多个连续盘块）为单位连成链。
   - 盘块分配与回收公式：
     - 分配公式：i=(b-1)DIVn + 1；j=(b-1)MODn + 1（i为组号，j为组内序号，b为盘块号，n为每组盘块数）。
     - 回收公式：b=n(i-1) + j。
3. **位示图法**：
   - 原理：用二进制的1位表示一个盘块的使用情况（1表示占用，0表示空闲），磁盘所有盘块对应一个二进制位序列。
4. **成组链接法**：
   - 原理：结合空闲表和空闲链表法，克服表太大的缺点；将顺序的n个空闲扇区地址保存在第一个空闲区内，下一个空闲区保存另一组顺序空闲扇区的地址（UNIX系统采用）。

### 4.3 磁盘组织与管理

#### 一、磁盘结构与分类

1. **磁盘结构**：

   - 物理组成：表面涂有磁性物质的金属/塑料圆形盘片，通过磁头（导体线圈）读取数据。
   - 存储单位：
     - 磁道：盘面上的同心圆，一个盘面有上千个磁道。
     - 扇区：磁道划分为几百个扇区，每个扇区固定存储大小，也称“盘块”。
   - 磁盘地址：用“柱面号-盘面号-扇区号（块号）”表示。
2. **磁盘分类**：

   - 按磁头是否移动：固定头磁盘（磁头径向固定）、活动头磁盘（每个磁道一个磁头，磁头可移动）。
   - 按盘片是否可更换：固定盘磁盘（盘片永久固定在驱动器内）、可换盘磁盘（盘片可移动替换）。

#### 二、磁盘读写时间组成

磁盘读写时间由三部分组成，公式如下：

1. **寻找时间（Ts）**：活动头磁盘将磁头移动到指定磁道的时间，Ts=mn + s（m为磁头移动速度，n为跨越磁道数，s为磁臂启动时间）。
2. **延迟时间（Tr）**：磁头定位到某一磁道扇区的时间，Tr=1/(2r)（r为磁盘转速，单位：转/秒）。
3. **传输时间（Tb）**：从磁盘读出或写入数据的时间，Tb=b/(rN)（b为传输数据量，N为一个磁道的扇区数）。

#### 三、磁盘调度算法

磁盘调度算法用于确定磁头服务请求的顺序，优化寻道时间，具体如下：

| 算法名称                 | 调度规则                                                                                 | 优缺点                                                                           |
| ------------------------ | ---------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 先来先服务（FCFS）       | 按进程请求访问磁盘的先后顺序调度                                                         | 优点：公平，实现简单；缺点：仅适用于少量进程，进程过多时倾向于随机调度，效率低   |
| 最短寻找时间优先（SSTF） | 选择与当前磁头所在磁道距离最近的请求作为下一次服务对象                                   | 优点：性能优于FCFS；缺点：容易产生饥饿现象（远磁道请求长期被忽略）               |
| 扫描（SCAN）算法         | 磁头沿当前移动方向，选择距离最近的请求服务；到达磁盘边缘后反向移动                       | 优点：寻道性能好，避免饥饿；缺点：对最近扫描过的区域不公平，访问局部性差         |
| 循环扫描（C-SCAN）算法   | 磁头单向移动，到达边缘后直接返回起始端（不服务返回途中的请求）                           | 优点：避免饥饿，请求响应更均匀；缺点：返回途中无服务，可能增加部分请求的等待时间 |
| LOOK算法                 | 在SCAN基础上优化：磁头沿当前方向移动时，检查前方是否有请求；无请求则改变方向             | 优点：减少不必要的磁头移动，提高效率；缺点：仍存在局部区域访问不均问题           |
| C-LOOK算法               | 在C-SCAN基础上优化：磁头单向移动，到达最远请求磁道后直接返回最近请求磁道（不返回起始端） | 优点：进一步减少磁头移动距离，效率更高；缺点：实现稍复杂                         |

#### 四、磁盘的管理

1. **磁盘初始化**：

   - 低级格式化：将磁盘分扇区，为每个扇区建立数据结构（头、数据区域、尾部），头部含磁盘控制器所需信息。
   - 分区：将磁盘划分为多个物理分区。
   - 逻辑格式化：对物理分区创建文件管理系统，包括空闲/已分配空间标记和初始空目录。
2. **引导块**：

   - 作用：计算机启动时，ROM中的自举程序初始化CPU、设备控制器和内存，然后加载启动块中的完整自举程序，启动操作系统。
   - 启动磁盘：拥有启动分区的磁盘，也称“系统磁盘”。
3. **坏块处理**：

   - 坏块：无法使用的扇区。
   - 处理方式：
     - 简单磁盘：逻辑格式化时检查坏块，在FAT表上标记；手动处理，程序不使用标记的坏块。
     - 复杂磁盘：控制器维护坏块链表，预留备用块替代坏块（扇区备用）。

#### 补充说明

- 盘面交替编号：磁头读写一个物理块后需短暂处理时间，交替编号可减少等待时间，提高效率。
- 磁头处理时间：磁头读写一个物理块后，需短暂处理时间才能处理下一块，是盘面交替编号的原因。
