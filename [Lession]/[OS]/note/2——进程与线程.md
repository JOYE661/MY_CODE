## 2.1 进程与线程（上）

### 进程的概念与特征

#### 进程的定义

- 进程是程序一次执行过程。
- 进程是一次程序及其数据在处理机上顺序执行时所发生的活动。
- 进程是具有独立功能的程序在一个数据集上运行的过程，是资源分配和调度的独立单位（未引入线程时）。

#### 进程的特征

1. **动态性**：动态性是进程最基本特征，进程有着创建、活动、暂停、终止等过程，具有生命周期。
2. **并发性**：多个进程实体同时存在于内存中，引入进程的目的就是为了让程序与其他程序并发执行。
3. **独立性**：进程实体是能独立运行、独立获得资源和独立接受调度的基本单位；未建立PCB的程序，不能作为独立单位参与运行。
4. **异步性**：进程相互制约，以不可预知的速度向前推进，因此操作系统必须配置相应的进程同步机制。
5. **结构性**：每个进程都配置一个PCB对其进行描述，进程实体由程序段、数据段、进程控制段（PCB）组成。

### 进程控制块（PCB）

- **定义**：为更好描述进程的基本情况和运行状态，进而控制和管理进程，**PCB是进程存在的唯一标志**。
- **PCB包含的信息**：| 信息类别           | 具体内容                                                                                                    |
  | ------------------ | ----------------------------------------------------------------------------------------------------------- |
  | 进程描述信息       | 进程标识符（标志进程）、用户标识符（进程所属用户，服务于共享和保护）、进程当前状态                          |
  | 进程控制和管理信息 | 进程优先级（描述进程抢占处理机的优先级）、代码运行入口地址、程序外存地址、进入内存时间、处理机占用时间      |
  | 资源分配清单       | 代码段指针、数据段指针、堆栈段指针、文件描述符、键盘/鼠标等I/O设备信息，说明内存/虚拟地址空间、打开文件列表 |
  | 处理机相关信息     | 通用寄存器值、地址寄存器值、控制寄存器值、标志寄存器值、状态字                                              |

### 进程的状态与转换

#### 进程的5种基本状态

1. **运行态**：进程在处理机上运行。
2. **就绪态**：进程已处于准备运行状态，等待获取处理机。
3. **阻塞态（等待态）**：进程正在等待某个事件（如I/O完成、中断结束）而暂停运行。
4. **创建态**：进程正在被创建，尚未进入就绪态。
5. **结束态**：进程正在从系统中消失（包括正常结束或异常终止）。

#### 状态相互转换

- 就绪态 → 运行态：处于就绪态的进程获得处理机，进入运行态。
- 运行态 → 就绪态：处于运行态的进程时间片用完，让出处理机，进入就绪态。
- 运行态 → 阻塞态：进程等待某事件（如申请I/O资源），主动放弃处理机，进入阻塞态。
- 阻塞态 → 就绪态：进程等待的事件发生（如I/O完成、中断结束），从阻塞态转为就绪态，等待调度。

### 进程控制

#### 1. 进程的创建

- **创建步骤**：
  1. 分配进程标识号，申请PCB（PCB资源有限）。
  2. 为进程分配资源，包括程序、数据及用户所需的内存空间。
  3. 初始化PCB：初始化标志信息、处理机状态信息、处理机控制信息，设置进程优先级。
  4. 若就绪队列可接纳新进程，进程进入就绪态。

#### 2. 进程的终止

- **终止分类**：
  - 正常结束：进程任务完成，准备退出运行。
  - 异常结束：进程运行中出现异常事件（如存储区越界、保护错、非法指令、特权指令、I/O故障等），无法继续运行。
  - 外界干预：进程应外界请求终止运行。
- **终止过程**：
  1. 若进程处于运行态，终止其运行，剥夺处理机。
  2. 根据被终止进程的标识符，检索PCB，读取进程状态。
  3. 终止该进程的所有子进程。
  4. 回收该进程拥有的全部资源，归还父进程或操作系统。
  5. 将该进程的PCB从队列中删除。

#### 3. 进程的阻塞和唤醒

- **阻塞原语执行过程**：

  1. 找到要被阻塞进程的标识符对应的PCB。
  2. 若该进程处于运行态，保护其现场，将状态转为阻塞态，停止运行（阻塞是进程自主行为）。
  3. 将PCB插入对应事件的等待队列。
- **唤醒原语执行过程**：

  1. 找到等待队列中目标进程的PCB。
  2. 将其从等待队列中移出，置状态为就绪态。
  3. 将PCB插入就绪队列，等待调度程序调度（唤醒由其他有联系的进程执行）。

#### 4. 进程切换

- **特点**：进程切换在内核态下完成。
- **切换过程**：
  1. 保存处理机上下文，包括程序计数器和其他寄存器的值。
  2. 更新当前进程的PCB信息。
  3. 将当前进程的PCB移入相应队列（如就绪队列、阻塞队列）。
  4. 选择另一个进程执行，更新其PCB信息。
  5. 更新内存管理的数据结构。
  6. 恢复选中进程的处理机上下文。

### 进程的组织

#### 进程实体的组成

- **程序段**：能被进程调度程序调度到CPU执行的程序代码段。
- **数据段**：进程对应的程序加工处理的原始数据，或执行时产生的中间/最终结果。
- **PCB**：进程存在的唯一标志，描述和控制进程。

#### 进程的组织方式

| 组织方式 | 实现逻辑                                                                               |
| -------- | -------------------------------------------------------------------------------------- |
| 链接方式 | 按照进程状态将PCB分为多个队列（如就绪队列、阻塞队列），操作系统持有指向各队列的指针    |
| 索引方式 | 根据进程状态建立几张索引表（如就绪索引表、阻塞索引表），操作系统持有指向各索引表的指针 |

## 2.1 进程与线程（中）

### 进程间通信

进程间通信用于实现进程间的信息交换，主要有3种方式：

#### 1. 共享存储

- **核心逻辑**：通信进程之间存在一块可直接访问的共享空间，操作系统仅提供共享存储空间和同步互斥工具，数据交换由用户通过读/写指令完成。
- **分类**：
  - 低级方式：基于数据结构共享（如共享数组、链表）。
  - 高级方式：基于存储区共享（共享一块连续的内存区域）。

#### 2. 消息传递

- **核心逻辑**：进程间的数据交换以格式化的“消息”为单位，通过系统提供的“发送消息”和“接收消息”原语实现。
- **分类**：
  - 直接通信方式：发送进程直接将消息发送给接收进程，并挂在接收进程的消息缓冲队列上；接收进程从消息缓冲队列中取消息。
  - 间接通信方式：发送进程将消息发送给中间实体（如邮箱、消息队列），接收进程从中间实体中获取消息（例：电子邮件系统）。
- **功能**：实现互斥、同步，确定通信对方存在。

#### 3. 管道通信

- **核心逻辑**：发送进程以字符流形式将大量数据写入“管道”，接收进程从管道中读取数据。
- **特性与限制**：
  - 管道为空时，读进程的 `read()`系统调用会被阻塞；管道满时，写进程的 `write()`系统调用会被阻塞。
  - 半双工通信：不能同时读和写。
  - 管道中的数据被读取后会立即被丢弃。
  - 管道大小固定，受系统限制。

### 线程基本概念

#### 引入线程的目的

减小程序并发执行时的时空开销，提高操作系统的并发性能。

#### 线程与进程的比较

| 对比维度     | 进程（引入线程后）                     | 线程                                             |
| ------------ | -------------------------------------- | ------------------------------------------------ |
| 调度单位     | 不是独立调度单位                       | 处理机的独立调度单位                             |
| 资源分配单位 | 系统资源的分配单位（拥有独立地址空间） | 不拥有系统资源，共享所属进程的资源               |
| 系统开销     | 进程切换开销大（需切换地址空间）       | 同一进程内线程切换开销小（共享地址空间）         |
| 并发性       | 进程间可并发                           | 进程内多个线程可并发，并发性能更高               |
| 地址空间     | 进程间地址空间相互独立                 | 同一进程的线程共享进程地址空间，对其他进程不可见 |
| 通信方式     | 需通过进程同步互斥工具（如信号量）辅助 | 可直接读/写进程的程序段/数据段，无需系统干预     |

#### 线程的属性

1. 线程是处理机的独立调度单位。
2. 同一进程的线程共享该进程拥有的全部资源（如内存、文件、I/O设备）。
3. 线程有生命周期，包括阻塞、就绪、运行等状态。
4. 不同线程可执行相同程序（如同一服务程序被不同用户调用时，系统创建不同线程）。
5. 多CPU计算机中，不同线程可占用不同CPU。
6. 每个线程有唯一标识符（线程ID）和线程控制块（TCB）。

### 线程的实现方式

| 实现方式   | 核心逻辑                                                                     |
| ---------- | ---------------------------------------------------------------------------- |
| 用户级线程 | 线程管理的所有工作由应用程序完成，内核意识不到线程的存在（依赖用户态线程库） |
| 内核级线程 | 线程的管理工作全部由内核完成（内核维护TCB，提供线程调度、同步等原语）        |

## 2.1 进程与线程（下）

### 多线程模型

多线程模型描述用户级线程（ULT）与内核级线程（KLT）的映射关系，主要有3种：

| 模型类型 | 映射关系                         | 优点                                | 缺点                                          |
| -------- | -------------------------------- | ----------------------------------- | --------------------------------------------- |
| 多对一   | 多个ULT映射到1个KLT              | 线程管理在用户空间完成，效率高      | 一个线程阻塞则全部线程阻塞；无法利用多CPU并行 |
| 一对一   | 1个ULT映射到1个KLT               | 并发能力强，可利用多CPU并行         | 创建线程开销大，影响应用程序性能              |
| 多对多   | 多个ULT映射到多个KLT（灵活分配） | 兼顾高并发与低开销，可利用多CPU并行 | 实现逻辑较复杂                                |

## 2.2 处理机调度（上）

### 调度的基本概念

调度的核心是“合理地对进程进行处理机分配”，确保系统高效运行。

### 调度的层次

根据调度对象和时机，分为3级调度：

| 调度层次 | 别称     | 核心逻辑                                                                                         | 特点                                     |
| -------- | -------- | ------------------------------------------------------------------------------------------------ | ---------------------------------------- |
| 作业调度 | 高级调度 | 从辅存中选择作业送入内存，为作业创建进程；每个作业只调入、调出各一次                             | 调度频率最低，为进程活动做准备           |
| 中级调度 | 内存调度 | 提高内存利用率：将暂时不能运行的进程调至外存（挂起态），或将具备运行条件的进程调入内存（就绪态） | 调度频率中等，处于作业调度与进程调度之间 |
| 进程调度 | 低级调度 | 从就绪队列中选取一个进程，将处理机分配给它                                                       | 最基本的调度，频率最高，不可或缺         |

### 调度的时机、切换与过程

#### 不能切换的情况

1. 进程在操作系统内核程序临界区时。
2. 其他需要完全屏蔽中断的原子操作过程中。

#### 可以切换的情况

1. 中断处理结束或自陷处理结束后。
2. 发生引起调度的条件（如时间片用完、高优先级进程进入就绪态），且当前进程无法继续执行。

#### 特殊规则

若需将处理机分配给更高优先级进程，必须等待当前占用处理机的进程主动释放处理机后才能进行。

### 进程调度方式

| 调度方式       | 核心逻辑                                                                   | 适用场景                 | 优缺点                                  |
| -------------- | -------------------------------------------------------------------------- | ------------------------ | --------------------------------------- |
| 非剥夺调度方式 | 一旦处理机分配给进程，便让其一直运行，直到进程完成或阻塞                   | 大多数批处理系统         | 实现简单、开销小；不适用于分时/实时系统 |
| 剥夺调度方式   | 若有更高优先级进程请求处理机，暂停当前运行进程，将处理机分配给高优先级进程 | 分时系统、大多数实时系统 | 提高系统吞吐率和响应效率；实现较复杂    |

### 调度的基本准则

调度准则用于衡量调度算法的优劣，核心指标如下：

| 准则名称         | 定义与计算方式                                                   | 作用                                       |
| ---------------- | ---------------------------------------------------------------- | ------------------------------------------ |
| CPU利用率        | （CPU忙碌时间 / 总时间）× 100%                                  | 尽可能保持CPU处于忙碌状态                  |
| 系统吞吐量       | 单位时间内CPU完成作业的数量                                      | 反映系统整体处理能力，受调度算法影响大     |
| 周转时间         | 作业从提交到完成的时间（周转时间 = 作业完成时间 - 作业提交时间） | 衡量作业等待与运行的总耗时                 |
| 平均周转时间     | （所有作业周转时间之和） / 作业总数                              | 反映调度算法对所有作业的整体公平性         |
| 带权周转时间     | 作业周转时间 / 作业实际运行时间（= 1 + 等待时间 / 实际运行时间） | 突出短作业的优势（短作业带权周转时间更小） |
| 平均带权周转时间 | （所有作业带权周转时间之和） / 作业总数                          | 更精准衡量调度算法的优劣                   |
| 响应时间         | 从用户提交请求到系统首次产生响应的时间                           | 关键指标（尤其分时系统、实时系统）         |
| 等待时间         | 作业等待处理机的时间（不含运行时间）                             | 直接影响用户体验，是算法优劣的核心衡量项   |

### 进程的挂起态与七状态模型

#### 挂起态的定义

暂时调到外存等待的进程状态，分为“就绪挂起”（具备运行条件但在外存）和“阻塞挂起”（等待事件且在外存）。

#### “挂起”与“阻塞”的区别

- 相同点：两种状态下进程均暂时无法获得CPU服务。
- 不同点：挂起态的进程映像（PCB+程序+数据）被调到外存；阻塞态的进程映像仍在内存中。

## 2.2 处理机调度（下）

### 典型调度算法

#### 1. 先来先服务（FCFS）算法

| 适用场景           | 核心逻辑                      | 优点                                                              | 缺点                                      |
| ------------------ | ----------------------------- | ----------------------------------------------------------------- | ----------------------------------------- |
| 作业调度、进程调度 | 按进程/作业到达顺序分配处理机 | 算法简单，对长作业有利；有利于CPU繁忙型（计算型）作业；无饥饿现象 | 效率低，不利于短作业；不利于I/O繁忙型作业 |
| 调度方式           | 非抢占式                      | -                                                                 | -                                         |

#### 2. 短作业优先（SJF）/ 短进程优先（SPF）算法

| 适用场景           | 核心逻辑                                                     | 优点                           | 缺点                                                                                       |
| ------------------ | ------------------------------------------------------------ | ------------------------------ | ------------------------------------------------------------------------------------------ |
| 作业调度、进程调度 | 优先选择预计运行时间最短的进程/作业                          | 平均等待时间、平均周转时间最短 | 对长作业不利，易造成“饥饿”现象；未考虑作业紧迫性；用户可能缩短作业预计时间，导致算法失效 |
| 调度方式           | 基础为非抢占式；抢占式版本为“最短剩余时间优先（SRTF）算法” | -                              | -                                                                                          |

#### 3. 优先级调度算法

| 核心逻辑                                 | 分类方式                                                                                | 优先级设置原则                                                                             | 优缺点                                                     |
| ---------------------------------------- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ | ---------------------------------------------------------- |
| 按进程优先级分配处理机，优先级高的先执行 | 按调度方式分：抢占式（高优先级进程可抢占CPU）、非抢占式（高优先级进程需等当前进程结束） | 1. 系统进程 > 用户进程；2. 交互型进程 > 非交互型进程；3. I/O进程 > CPU繁忙型（计算型）进程 | 优点：可优先处理关键进程；缺点：易造成低优先级进程“饥饿” |
|                                          | 按优先级是否可变分：静态优先级（进程创建后不可修改）、动态优先级（进程运行中可调整）    | -                                                                                          | -                                                          |

#### 4. 高响应比调度算法

| 核心逻辑                          | 响应比计算方式                                                                    | 优点                                                                                                                | 缺点                       |
| --------------------------------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- | -------------------------- |
| 优先选择“响应比最高”的进程/作业 | 响应比 = （等待时间 + 预计运行时间） / 预计运行时间 = 1 + 等待时间 / 预计运行时间 | 1. 等待时间相同：优先短作业；2. 预计运行时间相同：优先先到的作业；3. 长作业等待时间足够长时，响应比会升高，避免饥饿 | 需计算响应比，增加系统开销 |
| 调度方式                          | 非抢占式                                                                          | -                                                                                                                   | -                          |

#### 5. 时间片轮转（RR）算法

| 适用场景                 | 核心逻辑                                                                               | 时间片选择的影响因素                                      | 优缺点                                                                     |
| ------------------------ | -------------------------------------------------------------------------------------- | --------------------------------------------------------- | -------------------------------------------------------------------------- |
| 进程调度（尤其分时系统） | 就绪进程按到达顺序排队，依次在“时间片”内占用CPU；时间片结束则释放CPU，进入就绪队列尾 | 1. 系统响应时间；2. 就绪队列中的进程数目；3. 系统处理能力 | 优点：无饥饿现象，响应及时；缺点：时间片过大则退化为FCFS，过小则切换开销大 |
| 调度方式                 | 抢占式（时间片结束即抢占CPU）                                                          | -                                                         | -                                                                          |

#### 6. 多级反馈队列调度算法（融合型算法）

| 实现思想                                                                                                                                                                | 优点                                                                                          | 缺点                                                         | 调度方式                            |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------ | ----------------------------------- |
| 1. 设置多个就绪队列，优先级依次递减，每个队列的时间片依次递增；2. 各队列按FCFS排队，进程在当前队列时间片内未完成则转入下一级队列；3. 仅当高级队列为空时，才调度低级队列 | 1. 终端型作业（短作业）：优先执行；2. 短批处理作业：周转时间短；3. 长批处理作业：不会长期饥饿 | 低优先级进程仍可能因高级队列持续有进程而等待较久（轻度饥饿） | 抢占式（高级队列有新进程则抢占CPU） |

## 2.3 进程同步

### 基本概念

#### 1. 临界资源与临界区

- **临界资源**：一次只允许一个进程使用的资源（如打印机、特殊变量、共享数据）。
- **临界区**：进程中可以访问临界资源的代码段。
- **临界资源的访问过程**：
  1. 进入区：检查进程是否可进入临界区（如检查标志位）。
  2. 临界区：访问临界资源的代码。
  3. 退出区：清除“正在访问临界区”的标志。
  4. 剩余区：代码中的其余部分。

#### 2. 同步与互斥

- **同步（直接制约关系）**：为完成共同任务而建立的多个进程，相互合作、需按顺序执行（如“生产者-消费者”模型中，生产者生产后消费者才能消费）。
- **互斥（间接制约关系）**：多个进程竞争临界资源，一个进程访问时其他进程不能访问。

#### 3. 临界区互斥的原则

1. **空闲让进**：临界区空闲时，允许一个请求进入的进程立即进入。
2. **忙则等待**：已有进程进入临界区时，其他请求进程必须等待。
3. **有限等待**：请求访问临界区的进程，需在有限时间内进入。
4. **让权等待**：进程无法进入临界区时，立即释放处理机（避免忙等）。

### 实现临界区互斥的基本方法

#### 1. 软件实现方法

| 方法名称           | 核心逻辑                                                          | 优点                           | 缺点                                 |
| ------------------ | ----------------------------------------------------------------- | ------------------------------ | ------------------------------------ |
| 单标志法           | 设标志位指示当前可进入临界区的进程，进程交替进入                  | 实现简单                       | 违背“空闲让进”，资源利用率低       |
| 双标志法（先检查） | 进程先检查对方标志，若对方未请求则设置自身标志并进入临界区        | 无需交替进入，可连续使用资源   | 可能同时进入临界区，违背“忙则等待” |
| 双标志法（后检查） | 进程先设置自身标志，再检查对方标志，若对方请求则等待              | 不会同时进入临界区             | 可能相互谦让，导致“饥饿”           |
| 皮特森算法         | 在双标志法（后检查）基础上增加“-turn”标志，指定当前可进入的进程 | 解决饥饿现象，满足所有互斥原则 | 算法复杂，仅适用于2个进程            |

#### 2. 硬件实现方法

| 方法名称   | 核心逻辑                                                       | 优点                             | 缺点                                      |
| ---------- | -------------------------------------------------------------- | -------------------------------- | ----------------------------------------- |
| 中断屏蔽法 | 进程进入临界区前关中断，退出后开中断（禁止其他进程抢占CPU）    | 实现简单方便                     | 限制处理机交替执行能力，不适用于多CPU系统 |
| 硬件指令法 | 通过硬件指令（如“测试并置位”“交换”）原子性检查和设置标志位 | 简单且易验证正确性，支持多临界区 | 不能实现“让权等待”，可能导致饥饿        |

### 信号量

#### 1. 信号量的类型

| 类型         | 核心逻辑                                                                                                                                                                          | 特点                         |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------- |
| 整形信号量   | 用整形变量 `value`表示资源数目，`wait(S)`：`value-1`（若 `value<0`则忙等）；`signal(S)`：`value+1`                                                                    | 未遵循“让权等待”，进程忙等 |
| 记录型信号量 | 除 `value`外，增加进程链表 `L`链接等待进程；`wait(S)`：`value-1`（若 `value<0`则阻塞并加入 `L`）；`signal(S)`：`value+1`（若 `value<=0`则唤醒 `L`中一个进程） | 无忙等，遵循“让权等待”     |

#### 2. 信号量的应用

- **实现互斥**：设互斥信号量 `S=1`，进程进入临界区前执行 `wait(S)`，退出后执行 `signal(S)`，确保同一时间仅一个进程进入临界区。
- **实现同步**：设同步信号量 `S=0`，需先执行的进程P1执行完后调用 `signal(S)`，需后执行的进程P2在执行前调用 `wait(S)`，确保P1先于P2执行。
- **实现前驱关系**：为每个前驱关系设置信号量，前驱进程完成后发送信号，后继进程等待信号后执行（如进程A→B→C，设S1=0、S2=0，A执行完 `signal(S1)`，B执行前 `wait(S1)`、执行完 `signal(S2)`，C执行前 `wait(S2)`）。

### 管程

#### 1. 管程的定义

一组数据及定义在该数据上的操作组成的软件模块，能初始化并改变管程中的数据和同步，是一种高级同步机制。

#### 2. 管程的组成

1. 局部于管程的共享结构数据说明。
2. 对该数据结构进行操作的一组过程（函数）。
3. 对局部于管程的共享数据设置初始值的语句。

#### 3. 管程的基本特性

1. **封装性**：局部于管程的数据只能被管程内的过程访问。
2. **入口唯一性**：进程只能通过调用管程内的过程进入管程。
3. **互斥性**：每次仅允许一个进程在管程内执行某个内部过程（管程自动实现互斥）。

## 2.4 死锁

### 死锁的概念

#### 1. 死锁的定义

多个进程因竞争资源造成的“僵局”，若无外力作用，这些进程均无法向前推进（各进程互相等待对方释放资源）。

#### 2. 死锁产生的原因

1. **系统资源的竞争**：多个进程竞争有限的临界资源（如打印机、内存）。
2. **进程推进顺序非法**：进程执行顺序违反同步关系（如“生产者-消费者”模型中，消费者先于生产者执行）。

#### 3. 死锁产生的必要条件（4个缺一不可）

1. **互斥条件**：进程对分配的资源进行排他性控制（同一时间仅一个进程使用）。
2. **不可剥夺条件**：进程获得的资源未使用完前，不能被其他进程强行夺走。
3. **请求并保持条件**：进程已保持至少一个资源，又提出新的资源请求（该资源被其他进程占用），此时进程阻塞但不释放已持有的资源。
4. **循环等待条件**：多个进程形成资源请求循环（如A等B的资源，B等C的资源，C等A的资源）。

### 死锁的处理策略

死锁的处理策略分为“预防”“避免”“检测与解除”三类：

#### 1. 死锁预防

- **核心思想**：破坏死锁产生的4个必要条件中的一个或多个，从根源上防止死锁。
- **具体方法**：| 破坏的条件         | 实现方法                                                                 | 优缺点                                                                                                 |
  | ------------------ | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------ |
  | 破坏互斥条件       | 允许资源共享访问（仅适用于可共享的资源）                                 | 局限性大，部分资源（如打印机）必须互斥访问                                                             |
  | 破坏不可剥夺条件   | 进程请求新资源被拒时，释放已持有的资源；或系统强行剥夺低优先级进程的资源 | 优点：可避免死锁；缺点：增加系统开销，实现复杂，降低吞吐量（适用于CPU寄存器、内存等易保存/恢复的资源） |
  | 破坏请求并保持条件 | 进程创建时一次性申请所需全部资源，申请不到则不创建；运行中不申请新资源   | 优点：实现简单；缺点：资源严重浪费，进程初始化时间长，可能导致饥饿                                     |
  | 破坏循环等待条件   | 采用“顺序资源分配法”：对所有资源编号，进程按编号递增顺序申请资源       | 优点：可避免循环等待；缺点：进程编号需稳定，资源利用率低，不利于用户编程                               |

#### 2. 死锁避免

- **核心思想**：在资源动态分配过程中，预测分配后是否会进入“不安全状态”，若会则拒绝分配，避免死锁。
- **关键概念**：
  - **安全状态**：存在一个“安全序列”（进程按此序列分配资源可全部完成）。
  - **不安全状态**：不存在安全序列，可能发生死锁。
- **典型算法：银行家算法**：
  - 思想：类比银行贷款，确保分配资源后银行仍有足够资金满足其他客户的贷款需求；系统分配资源前，检查分配后是否存在安全序列，若存在则分配，否则拒绝。
  - 优点：无需剥夺资源，资源利用率较高。
  - 缺点：需提前知道进程的最大资源需求，进程不能长时间阻塞。

#### 3. 死锁的检测与解除

- **核心思想**：允许系统发生死锁，通过检测及时发现死锁，再采取措施解除。

##### （1）死锁检测

- **工具：资源分配图**：
  - 节点：圆圈表示“进程”，方框表示“一类资源”（方框内的小圆圈表示资源实例数）。
  - 边：进程→资源的有向边为“请求边”（进程请求资源），资源→进程的有向边为“分配边”（资源已分配给进程）。
- **死锁定理**：对资源分配图进行“简化”（找到能完成的进程，消去其请求边和分配边），若最终所有边都能消去，则图可简化，无死锁；否则存在死锁。
- **检测时机**：定期检测（如每隔固定时间）或按需检测（如进程请求资源被拒时）。

##### （2）死锁解除

- **常用方法**：| 解除方法   | 核心逻辑                                                                      | 优缺点                                                   |
  | ---------- | ----------------------------------------------------------------------------- | -------------------------------------------------------- |
  | 资源剥夺法 | 挂起部分死锁进程，抢占其资源分配给其他死锁进程                                | 优点：无需撤销进程；缺点：需防止被挂起进程等待过久       |
  | 撤销进程法 | 强制撤销部分/全部死锁进程，回收其资源；按“优先级”或“撤销代价”选择撤销对象 | 优点：简单直接；缺点：可能造成数据丢失和计算损失         |
  | 进程回退法 | 让一个/多个进程回退到足以回避死锁的“还原点”，自愿释放资源                   | 优点：损失较小；缺点：需系统保存进程历史信息，设置还原点 |

### 死锁、饥饿、死循环的区别

| 概念   | 定义                                                     | 产生原因                                     | 解决方式                                     |
| ------ | -------------------------------------------------------- | -------------------------------------------- | -------------------------------------------- |
| 死锁   | 多个进程互相等待对方资源，均无法推进                     | 资源竞争+推进顺序非法（满足4个必要条件）     | 预防、避免、检测与解除                       |
| 饥饿   | 某进程长期得不到所需资源，无法推进                       | 调度算法不公平（如优先级调度中低优先级进程） | 改进调度算法（如高响应比调度），确保有限等待 |
| 死循环 | 进程执行中一直跳不出某个循环（如逻辑错误导致的无限循环） | 程序逻辑错误                                 | 调试程序，修正逻辑错误                       |
