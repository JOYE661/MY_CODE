# 操作系统相关基础内容

## 1.1 操作系统的基本概念

### 1.1.1 操作系统的概念

操作系统是**合理地组织、调度计算机的工作与资源，为用户和其他软件提供方便接口与环境的程序集合**，核心作用是**控制和管理整个计算机系统的硬件与软件资源**。

### 1.1.2 操作系统的基本特征

操作系统具有四大基本特征：并发、共享、虚拟、异步，具体说明如下：

- **并发**

  - 定义：两个或者多个事件在**同一时间间隔内**发生（区别于“并行”）。
  - 实现方式：操作系统的并发通过“分时”实现，使系统具备处理和调度多个程序“同时”执行的能力。
  - 核心区别：
    - 并发：时间段内交替执行（如单核CPU）；
    - 并行：**同一时刻**同时执行（需硬件支持，如多流水线、多处理机）。
  - 硬件关联：
    - 单核CPU：同一时刻只能执行一个程序，宏观上程序并发（用户感知“同时”），微观上程序交替执行；
    - 多核CPU：同一时刻可同时执行多个程序，多个程序可并行执行。
- **共享**

  - 定义：系统中的资源（硬件/软件）可被多个并发执行的程序共同使用。
  - 两种共享方式（重要考点）：
    1. 互斥共享方式：一段时间内仅允许一个进程访问资源，这类资源称为**临界资源（或独占资源）**，例如打印机、磁带；
    2. 同时访问方式：一段时间内允许多个进程对资源进行访问，例如磁盘设备、重入码编写的文件。
- **虚拟**

  - 定义：通过“虚拟技术”将一个物理上的实体，变为若干个逻辑上的对应物，从而提升资源利用率。
  - 典型应用：
    - 虚拟I/O设备：将一台物理I/O设备虚拟为多台逻辑I/O设备，允许每个用户占用一台逻辑I/O设备；
    - 虚拟处理器：采用多道程序并发方式，让每个终端用户“感觉”有专属处理器；
    - 虚拟存储器：将物理存储扩展为虚拟存储器，从逻辑上扩充存储容量。
  - 核心技术：空分复用技术、时分复用技术。
- **异步**

  - 定义：多道程序环境中，进程的执行呈现“走走停停”的特点，进程以**不可预知的速度**向前推进（因进程调度、资源竞争等因素）。

### 1.1.3 操作系统的目标和功能

操作系统的核心目标是“提高多道程序运行效率，方便用户使用”，主要功能分为**管理功能**、**接口功能**和**封装思想**三类。

#### 1. 管理功能

操作系统通过四大管理模块，实现对系统资源的高效控制：

| 管理模块   | 核心职责                                                                                                           |
| ---------- | ------------------------------------------------------------------------------------------------------------------ |
| 处理机管理 | 管理处理机的分配与运行，解决资源冲突，本质是“进程管理”，包括：进程控制、进程同步、进程通信、死锁处理、处理机调度 |
| 存储器管理 | 负责内存资源的管理，包括：内存分配、地址映射、内存保护、内存共享、内存扩充                                         |
| 设备管理   | 完成用户I/O请求，提高设备利用率，包括：缓冲管理、设备分配、设备处理、虚拟设备                                      |
| 文件管理   | 操作系统中负责管理文件的模块称为“文件系统”，包括：文件存储空间管理、目录管理、文件读写管理、文件保护             |

#### 2. 接口功能

操作系统为用户和软件提供两类接口，实现“扩充机器”的作用（覆盖软件的机器称为**扩充机器/虚拟机**）：

- **程序接口**：由一组系统调用命令组成（又称“系统调用”或“广义指令”），供用户程序调用操作系统功能。
- **命令接口**：供用户直接操作计算机，分为两类：
  1. 脱机控制方式：又称“批处理系统”，用户提交一组作业后，系统自动处理，用户无法干预作业运行；
  2. 联机控制方式：又称“交互式命令接口”，适用于分时/实时系统，支持人机对话（如图形用户界面GUI）。

#### 3. 封装思想

操作系统将底层硬件功能封装为“简单易用的服务”，用户无需关心硬件原理，仅需向操作系统发出命令即可使用计算机（屏蔽硬件复杂性）。

## 1.2 操作系统的发展与分类（VIP）

操作系统的发展经历多个阶段，各阶段针对前一阶段的痛点优化，核心是解决“人机矛盾”和“CPU与I/O设备速度不匹配矛盾”，具体分类如下：

### 1.2.1 手工操作阶段

- 核心特点：程序的装入、运行、结果输出均需**人为干预**。
- 缺点：资源利用率低、CPU利用不充分（CPU常处于空闲状态）。

### 1.2.2 批处理阶段

该阶段通过“成批处理作业”减少人工干预，分为“单道批处理系统”和“多道批处理系统”：

#### 1. 单道批处理系统

- 核心机制：内存中始终保存一道作业，作业成批处理。
- 特点：
  - 自动性：一批作业自动执行，无需人工干预；
  - 顺序性：各道作业依次执行（前一道结束后，后一道才调入）；
  - 单道性：内存中仅有一道程序执行。
- 优点：缓解一定程度的人机速度矛盾，资源利用率有所提升。
- 缺点：高速CPU需等待I/O设备完成（I/O速度慢，CPU空闲时间长）。

#### 2. 多道批处理系统

- 核心机制：内存中同时存放多道相互独立的程序，允许多个程序在CPU中交替运行，共享硬件/软件资源。
- 特点：
  - 宏观上并行：多道程序均已启动，但均未运行完毕（用户感知“同时执行”）；
  - 微观上串行：多道程序轮流占有CPU，交替执行。
- 优点：
  - 资源利用率高（多道程序并发执行，共享资源）；
  - CPU和其他资源保持“忙碌”状态，系统吞吐量增大。
- 缺点：
  - 设计复杂（需解决资源调度、死锁等问题）；
  - 响应时间过长，无一人机交互功能。

### 1.2.3 分时操作系统

- 核心机制：将处理器运行时间划分为“时间片”，按时间片分配给不同作业/用户，实现CPU共享。
- 特点：
  - 同时性：允许多个终端用户使用同一台计算机；
  - 交互性：支持人机对话，用户可实时控制程序运行；
  - 独立性：多个用户操作彼此独立，互不干扰；
  - 及时性：用户请求能在很短时间内获得响应。

### 1.2.4 实时操作系统

- 核心目标：保证在**规定时间内**完成某项任务（满足实时性需求）。
- 特点：
  - 及时性：严格在规定时间内完成规定任务（实时性要求高于分时系统）；
  - 可靠性：输出结果正确，系统运行稳定（不允许出错或延迟）。

### 1.2.5 其他类型操作系统

- **网络操作系统**：将多个计算机有机结合，实现资源共享和远程通信。
- **分布式计算机系统**：任意两台计算机无主从之分，可互相交换信息、并行工作、协同完成任务。
- **个人计算机操作系统**：广泛应用于个人设备，支持文字处理、电子表格、游戏等功能（用户友好，界面直观）。

## 1.3 操作系统的运行环境（VIP）

### 1.3.1 程序运行的本质

程序运行的过程，本质是**CPU执行一条又一条机器指令的过程**。

### 1.3.2 操作系统的运行机制

#### 1. CPU执行的两类程序

- 操作系统内核程序：运行于“内核态”，可执行特权指令；
- 用户自编程序：运行于“用户态”，仅可执行非特权指令。

#### 2. 中断机制

- 初衷：提高多道程序运行环境中的CPU利用率。
- 核心作用：“中断”是操作系统内核**夺回CPU使用权的唯一途径**（触发中断后，CPU从用户态切换到内核态）。
- 时钟管理：操作系统通过时钟提供标准时间，并根据时钟管理进程（如时间片到后触发进程切换）。
- 中断处理：保护和恢复中断现场信息，将控制权转移到相关处理程序。

#### 3. 原语

- 定义：运行具有“原子性”的操作（只能一气呵成，不可中断）。
- 核心功能：
  - 进程管理：进程状态管理、进程调度与分派、创建/撤销进程；
  - 存储器管理：存储器空间分配与回收、内存信息保护程序、代码对换程序；
  - 设备管理：缓冲区管理、设备分配与回收。

#### 4. 系统控制的数据结构及处理

围绕上述管理功能，操作系统通过维护各类数据结构（如进程控制块PCB、内存分配表）实现资源调度与管理。

### 1.3.3 中断与异常

中断和异常是触发“用户态→内核态”切换的关键事件，二者区别如下：

| 类型           | 触发来源              | 常见场景                                      | 屏蔽性   |
| -------------- | --------------------- | --------------------------------------------- | -------- |
| 中断（外中断） | CPU指令之外的事件     | I/O中断（输入输出完成）、时钟中断（时间片到） | 可屏蔽   |
| 异常（内中断） | CPU执行指令内部的事件 | 非法操作码、除零错误、地址越界、算术溢出      | 不可屏蔽 |

- 特殊异常：**陷入指令**（用户自行设置，执行后主动从用户态切换到内核态，用于调用系统服务）。

### 1.3.4 系统调用

系统调用是用户程序访问操作系统内核功能的“接口”，用户在程序中通过调用系统调用，间接使用底层硬件/软件资源，核心功能包括：

- 设备功能：完成设备的请求、释放、启动等；
- 文件管理：完成文件的读、写、创建、删除等；
- 进程控制：完成进程的创建、撤销、阻塞、唤醒等；
- 进程通信：完成进程间的消息传递、信号传递等；
- 内存管理：完成内存的分配、回收，以及获取作业占用内存的大小和起始地址等。

### 1.3.5 用户态与内核态

#### 1. 核心定义与别名

- 内核态：又称“核心态”“管态”，此时运行的是内核程序，可执行**特权指令**（如修改CPU状态、访问硬件资源）；
- 用户态：又称“目态”，此时运行的是应用程序，仅可执行**非特权指令**（如普通运算、数据读写）。

#### 2. 状态标识

CPU中有一个“程序状态字寄存器（PSW）”，其中一个二进制位用于标识状态：

- 1：表示内核态；
- 0：表示用户态。

#### 3. 内核态与用户态的切换

- 内核态 → 用户态：执行一条特权指令，修改PSW的标志位为“用户态”（操作系统主动让出CPU使用权）；
- 用户态 → 内核态：由“中断/异常”引发，**硬件自动完成状态切换**（触发中断信号后，操作系统强行夺回CPU使用权）。

> 注意：访管指令在用户态使用，用于触发用户态→内核态切换，但访管指令**不是特权指令**（特权指令仅能在内核态执行）。

## 1.4 大内核与微内核（VIP）

随着计算机体系结构发展，操作系统服务增多、接口复杂，衍生出“大内核”和“微内核”两种架构：

### 1.4.1 大内核

- 核心设计：将操作系统的**主要功能模块集中在内核中**，直接运行于核心态。
- 优点：各管理模块共享信息，能有效利用彼此特性，**性能优势显著**（减少状态切换开销）。
- 缺点：层次交互关系复杂，层次接口难以定义，层次间界限模糊，维护难度大。

### 1.4.2 微内核

- 背景：为解决大内核的复杂性问题，简化内核设计。
- 核心设计：仅将内核中**最基本的功能（如进程管理、中断处理）保留在内核态**，将不需要在核心态执行的功能（如文件管理、设备驱动）转移到用户态执行。
- 优点：
  - 有效分离“内核与服务”“服务与服务”，接口清晰，维护代价大大降低；
  - 各部分可独立优化和演进（模块化程度高）。
- 缺点：性能问题——用户态与核心态之间需频繁切换（服务调用需跨状态），增加开销。
