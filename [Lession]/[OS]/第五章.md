# 第五章 IO管理相关内容

## 一、设备基础分类

### 1. 按功能与用途分类

| 设备类型               | 功能描述                   | 交换速度       | 数据交换单位   | 常见设备示例         |
| ---------------------- | -------------------------- | -------------- | -------------- | -------------------- |
| 人机交互外部设备       | 用于计算机与用户之间的交互 | 相对较慢       | 字节           | 打印机、鼠标、键盘   |
| 存储设备               | 用于存储程序和数据         | 较快           | 多字节组成的块 | 磁盘、磁带、光盘     |
| 网络通信设备（IO设备） | 用于与远程设备进行通信     | 介于前两类之间 | -              | 网络接口、调制解调器 |

### 2. 按传输速率分类

- **低速设备**：传输速率为每秒几个字节到数百字节，如鼠标、键盘。
- **中速设备**：传输速率为每秒数千字节至数万字节，如行式打印机、激光打印机。
- **高速设备**：传输速率在数百兆字节至千兆字节，如磁带机、磁盘机、光盘机。

### 3. 按信息交换单位分类

| 设备类型 | 定义                                     | 传输速率 | 可寻址性 | 输入输出方式   | 常见设备示例         |
| -------- | ---------------------------------------- | -------- | -------- | -------------- | -------------------- |
| 字符设备 | 用于数据输入输出，传输基本单位为字符     | 低       | 不可寻址 | 中断驱动方式   | 交互式终端机、打印机 |
| 块设备   | 信息存取以数据块为基本单位，用于存储信息 | 高       | 可寻址   | 可任意读写某块 | 磁盘、磁带、光盘     |

## 二、IO控制方式

计算机从外部设备读取数据到存储器时，默认每次读一个字的数据，CPU需循环检查外设状态，确认字已在IO设备控制器的数据寄存器中。以下为四种核心IO控制方式：

| 控制方式         | 读写单位 | 核心特点                                                                                                                                 | 优点                              | 缺点                                                                |
| ---------------- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------- | ------------------------------------------------------------------- |
| 程序直接控制方式 | 字       | CPU需循环检查外设状态，IO设备与CPU串行工作                                                                                               | 容易实现，操作简单                | CPU高速性与IO设备低速性矛盾，降低CPU利用率，CPU与IO设备只能串行工作 |
| 中断驱动方式     | 字       | IO设备可主动打断CPU运行并请求服务，CPU发送读命令后可做其他工作                                                                           | 比程序直接控制方式更有效          | 数据传输必须经过CPU，仍消耗CPU时间                                  |
| DMA方式          | 数据块   | 1. 在IO设备和内存间开直接数据交换通路，彻底解放CPU；`<br>`2. 仅数据块开始/结束时CPU干预；`<br>`3. 需4个关键寄存器（MAR、DR、CR、DC） | 大幅减少CPU干预，提高数据传输效率 | -                                                                   |
| 通道控制方式     | 一组块   | 1. 设置专门IO处理机（DMA方式的发展）；`<br>`2. 实现对一组数据块的读写及控制管理                                                        | 有效提高系统资源利用率            | 实现较为复杂                                                        |

### 补充：DMA与通道的区别

1. 控制权限：DMA需CPU控制传输的数据块大小、内存位置；通道方式中这些信息由通道自主控制。
2. 设备管理范围：DMA控制器对应一台设备与内存传递数据；通道可控制多台设备与内存的数据交换。

### DMA方式关键寄存器说明

- **内存地址寄存器（MAR）**：实现数据在设备与内存之间直接交互。
- **数据寄存器（DR）**：暂存从设备到内存或从内存到设备的数据。
- **命令/状态寄存器（CR）**：接收CPU发送的IO命令、控制信息，或存储设备状态。
- **数据计数器（DC）**：存放本次要传送的字（节）数。

## 三、IO子系统层次结构（5.1 IO管理概述（下））

IO子系统从上层到下层分为5个层次，各层次功能明确且相互协作：

### 1. 层次划分及功能

| 层次           | 核心功能                                                                                                                                                                                                                                                                                                                                     |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 用户层IO软件   | 实现与用户交互的接口；用户可直接调用IO操作相关库函数对设备进行操作                                                                                                                                                                                                                                                                           |
| 设备独立性软件 | 1. 实现用户程序与设备驱动器的统一接口、设备命令、设备保护及分配/释放；`<br>`2. 提供IO数据传送所需存储空间；`<br>`3. 实现**设备独立性（设备无关性）**，应用程序使用逻辑设备名而非物理设备名；`<br>`4. 执行设备公有操作（分配/回收、逻辑-物理设备名映射、设备保护、禁止用户直接访问设备）；`<br>`5. 屏蔽设备间数据交换的速度差异 |
| 设备驱动程序   | 与硬件直接相关；负责实现系统对设备的操作命令，驱动IO设备工作                                                                                                                                                                                                                                                                                 |
| 中断处理程序   | 1. 保存被中断进程的CPU环境，转入对应中断处理程序；`<br>`2. 处理完成后恢复进程现场，返回被中断进程                                                                                                                                                                                                                                          |
| 硬件设备       | IO设备通常包含**机械部件**和**电子部件**；接收并执行CPU或通道发来的命令（如磁盘读写、查找命令）                                                                                                                                                                                                                                  |

### 2. 设备控制器（IO设备核心组件）

#### （1）设备控制器功能

- 接收和识别CPU或通道发来的命令（如磁盘读写、查找命令）。
- 实现设备与控制器、控制器与主存之间的数据交换。
- 发现和记录设备及自身的状态信息，供CPU处理。
- 实现设备地址识别。

#### （2）设备控制器接口

| 接口类型     | 包含信号类型                   | 说明                                                   |
| ------------ | ------------------------------ | ------------------------------------------------------ |
| 与CPU的接口  | 数据线、信号线、地址线、控制线 | 通过控制线与CPU交互，对CPU发来的IO命令进行解码         |
| 与设备的接口 | 数据信号、控制信号、状态信号   | 每个接口均包含这三类信号，一个设备控制器可对应多个设备 |

#### （3）设备控制器组成

- **IO控制逻辑**：实现对设备的控制，解码CPU发来的IO命令。
- 寄存器组：包含数据寄存器、控制寄存器、状态寄存器（可能有多个，需分配地址供CPU操作）。

#### （4）寄存器地址分配方式

- **内存映像IO**：寄存器占用内存地址的一部分。
- **IO专用地址**：寄存器独立编址，不占用内存地址。

## 四、IO核心子系统（5.2 IO核心子系统（上））

IO核心子系统主要提供**IO调度、缓冲与高速缓存、设备分配与回收、设备保护、差错处理**等功能。

### 1. IO调度

- **概念**：通过调度策略改善系统整体性能，实现进程公平共享设备访问，减少IO完成所需的平均等待时间。
- **优化技术**：使用主存或磁盘存储空间（如缓冲、高速缓存、假脱机技术）提升计算机效率。

### 2. 高速缓存与缓冲区

#### （1）磁盘高速缓存

- **定义**：逻辑上属于磁盘，物理上驻留在内存中的缓存区域；访问高速缓存比访问原始磁盘数据更高效，可提高磁盘IO速度。
- **内存中的两种形式**：
  1. 将未利用的内存空间作为缓冲，供请求分页系统和磁盘IO共享。
  2. 在内存中开辟单独固定大小的存储空间作为磁盘高速缓存。

#### （2）缓冲区

- **定义**：位于内存区域（或硬件缓冲器，成本高，仅关键位置使用），用于设备与处理机之间的数据暂存；设备与处理机交换数据时，先写入缓冲区，再由需求方读取。
- **引入目的**：

  1. 提高处理机和输入设备的并行操作程度。
  2. 减少对CPU的中断频率，放宽CPU中断响应时间限制。
  3. 解决CPU与IO设备之间的速度差异矛盾。
  4. 解决基本数据单元大小不匹配的问题。
- **缓冲区分类及特点**：

  | 缓冲区类型 | 核心特点                                                                                                                                                                                                       | 时间计算（参数：T=数据写入缓冲区时间；C=CPU处理数据时间；M=缓冲区数据传入用户区时间） |
  | ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
  | 单级缓冲   | 仅设置一个缓冲区；需缓冲区满后才能取出数据                                                                                                                                                                     | max(C + M, T)                                                                         |
  | 双缓冲     | 设置两个缓冲区；缓冲区1满时向缓冲区2注入数据，并行性更高                                                                                                                                                       | max(C, T) + M                                                                         |
  | 循环缓冲   | 包含多个大小相等的缓冲区；每个缓冲区指向next，形成环形；交替读写                                                                                                                                               | -                                                                                     |
  | 缓冲池     | 1. 包含四种缓冲区：收容输入数据的工作缓冲区、提取输入数据的工作缓冲区、收容输出数据的工作缓冲区、提取输出数据的工作缓冲区；`<br>`2. 分为三个队列：空缓冲队列、装满输入数据的缓冲队列、装满输出数据的缓冲队列 | -                                                                                     |
- **特殊说明**：管道通信中的“管道”本质是缓冲区；需实现数据双向传输时，必须设置两个管道。

### 3. 设备分配与回收

#### （1）设备类型分类（按使用方式）

- **独占式使用设备**：一个时段只能分配给一个进程，如打印机（需互斥使用）。
- **分时共享使用设备**：通过分时共享提高利用率，如磁盘（宏观同时共享，微观交替使用）。
- **SPOOLing方式使用设备**：用空间换时间，对IO设备进行批处理（后续详细说明）。

#### （2）设备分配数据结构

四种核心表结构，相互关联实现设备分配：

| 表结构名称           | 功能描述                                   | 关联关系                                                            |
| -------------------- | ------------------------------------------ | ------------------------------------------------------------------- |
| 设备控制表（DCT）    | 表征一个设备，记录设备各项属性             | 与控制器控制表（COCT）一一对应，DCT含指向COCT的指针                 |
| 控制器控制表（COCT） | 记录控制器属性及状态                       | 与DCT一一对应；关联通道控制表（CHCT），对应CHCT提供服务的设备控制器 |
| 通道控制表（CHCT）   | 记录通道属性及状态；管理其服务的设备控制器 | 关联COCT，一个CHCT对应多个COCT                                      |
| 系统设备表（SDT）    | 记录已连接到系统的所有物理设备的情况       | 涵盖所有设备的DCT信息，是设备分配的总入口                           |

#### （3）设备分配策略

| 策略类型 | 分类           | 特点                                                                 | 适用场景             |
| -------- | -------------- | -------------------------------------------------------------------- | -------------------- |
| 分配方式 | 静态分配       | 系统一次性将设备分配给作业，直至作业结束；无死锁问题，但设备利用率低 | 独占设备             |
|          | 动态分配       | 进程执行中根据需求分配；设备利用率高，但可能因算法不当导致死锁       | 共享设备             |
| 分配算法 | 先请求先分配   | 类似“先来先服务”，按请求顺序分配                                   | 各类设备通用         |
|          | 优先级高者优先 | 优先级高的进程优先获得设备；可能导致低优先级进程“饥饿”             | 对实时性要求高的场景 |
| 分配原则 | -              | 核心原则：充分发挥设备效率，避免进程死锁                             | -                    |

#### （4）设备分配的安全性

| 分配方式       | 特点                                           | 优点                     | 缺点                        |
| -------------- | ---------------------------------------------- | ------------------------ | --------------------------- |
| 安全分配方式   | 进程发出IO请求后进入阻塞态，直至IO结束被唤醒   | 设备分配安全，无死锁风险 | CPU与IO设备串行工作，效率低 |
| 不安全分配方式 | 进程发出IO请求后继续运行，可后续发出多个IO请求 | 进程推进迅速，并行性高   | 可能产生死锁                |

## 五、IO核心子系统（下）

### 1. 逻辑设备名到物理设备名的映射

- **目的**：
  1. 提高设备分配的灵活性和利用率。
  2. 实现**设备独立性**（应用程序无需关注物理设备）。
  3. 实现IO重定向（如将输出从屏幕重定向到打印机）。
- **实现方法**：引入**逻辑设备表（LUT）**，记录逻辑设备名与物理设备名的映射关系。
- **LUT建立方式**：
  1. 系统级LUT：整个系统设一张表，记录所有设备分配情况（适用于单用户系统）。
  2. 用户级LUT：为每个用户建立一张表，记录该用户的设备分配情况（适用于多用户系统）。

### 2. SPOOLing技术（假脱机技术）

- **核心前提**：必须依赖多道程序技术的支持。
- **目的**：缓解CPU与IO设备的速度差异矛盾；将独占设备改造为虚拟共享设备。
- **组成部分**（5大组件，协同实现数据暂存与传输）：

  | 组成部分          | 功能描述                                                                                                                                                             |
  | ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
  | 输入井            | 磁盘上的存储空间，用于收容IO设备输入的数据                                                                                                                           |
  | 输出井            | 磁盘上的存储空间，用于模拟输出时的“虚拟设备”，暂存待输出数据                                                                                                       |
  | 输入缓冲区        | 内存中的缓冲区，暂存由输入设备送来的数据，再传入输入井                                                                                                               |
  | 输出缓冲区        | 内存中的缓冲区，暂存从输出井送来的数据，再传入输出设备                                                                                                               |
  | 输入进程/输出进程 | 输入进程：模拟脱机输入的外围控制机，将输入设备数据经输入缓冲区送入输入井；`<br>`输出进程：模拟脱机输出的外围控制机，将内存数据送入输出井，待设备空闲时传入输出设备 |
- **特点**：

  1. 提高IO速度：数据先暂存于磁盘（输入井/输出井），避免CPU等待设备。
  2. 实现设备共享：将独占设备（如打印机）改造为虚拟共享设备，多进程可同时“使用”。
  3. 空间换时间：用磁盘空间暂存数据，换取CPU与IO设备的并行工作时间。

### 3. 高速缓存与缓冲区对比

| 对比维度        | 高速缓存                                                                      | 缓冲区                                                                                               |
| --------------- | ----------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 相同点          | 均介于高速设备（如CPU、内存）和低速设备（如磁盘、键盘）之间，用于缓解速度差异 | 均介于高速设备（如CPU、内存）和低速设备（如磁盘、键盘）之间，用于缓解速度差异                        |
| 不同点-存放数据 | 存放低速设备上某些数据的**复制数据**（如磁盘数据的内存副本）            | 存放低速设备传递给高速设备的**原始数据**（低速设备上不一定有备份），数据需从缓冲区传入高速设备 |
| 不同点-目的     | 存放高速设备经常访问的数据；若缓存中无数据，高速设备需直接访问低速设备        | 高速设备与低速设备的通信必须经过缓冲区，高速设备**永远不直接访问**低速设备                     |
