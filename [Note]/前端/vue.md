1. API 层的标准化 (src/api/employee.ts)

  我们首先定义了与后端交互的接口。

* 动作: 将原 Vue 2 项目的 API 只有登录/登出的定义，扩展为完整的 CRUD（增删改查）。
* 关键点:
  * getEmployeeList: 查列表 (GET)。
  * addEmployee / editEmployee: 增/改 (POST/PUT)。
  * enableOrDisableEmployee: 状态控制 (POST)。
  * 规范化: 所有接口都复用了我们之前封装好的 request.ts，这意味着它们自动拥有了 Token 注入、超时拦截、401 跳转等能力。

2. 列表页迁移 (src/views/employee/index.vue)

  这是用户最先看到的页面。我们从 Vue 2 的 Class Component 写法重构为 Vue 3 的 Script Setup 写法。

* 核心逻辑:
  * 响应式数据: 使用 ref 和 reactive 定义 tableData (列表数据)、queryParams (搜索条件) 和 loading (加载状态)。
  * 生命周期: 使用 onMounted 替代了原来的 created，在组件挂载后立即触发 fetchData。
  * 操作反馈: 引入 ElMessage 和 ElMessageBox。例如在点击“禁用”时，先弹窗询问“确认要禁用吗？”，用户点确定后再调用
    API，成功后提示“操作成功”并刷新列表。
* 模板变化:
  * Element Plus: 标签名没变（还是 `<el-table>`），但属性绑定方式更规范了（如 v-model:current-page 替代了原来的 .sync
    修饰符）。
  * 作用域插槽: 新版使用了 #default="scope" 语法，替代了旧的 slot-scope="scope"。

3. 新增/编辑页迁移 (src/views/employee/add.vue)

  这是一个复杂的表单页面，也是最能体现 Vue 3 优势的地方。

* 单一文件处理双模式: 我们用一个 add.vue 文件同时处理 “新增” 和 “修改” 两种场景。
  * 判断逻辑: 通过 route.query.id 是否存在来判断。如果有 ID，就是修改模式，自动调用 queryEmployeeById 回显数据。
* 表单验证:
  * 定义了 rules 对象，并在 el-form 上绑定。
  * 编写了自定义验证函数（validatePhone, validateID），确保手机号和身份证格式正确。
* 提交逻辑:
  * 点击保存时，先调用 formEl.validate()。验证通过后，根据模式调用 addEmployee 或 editEmployee。
  * 细节: 实现了“保存并继续添加”功能，保存成功后不跳转，而是清空表单（formEl.resetFields()），方便连续录入。

4. 路由与菜单的协同 (Sidebar Fix)

  这是一个底层的架构调整，为了解决 “路由嵌套显示” 的问题。

* 问题: 我们的路由结构是 /employee (父) -> index (列表) + add (新增)。
  * 如果不处理，侧边栏可能会显示出“员工管理”下面还有一个“员工管理”子菜单，或者把“添加员工”也显示在菜单里。
* 解决方案:
  * 在 router/index.ts 里，给 add 路由加上 meta: { hidden: true }。
  * 关键修改: 优化了 SidebarItem.vue 组件。它现在会智能判断：如果一个父路由只有一个 可见 的子路由（过滤掉 hidden
    的），那么它就直接把自己显示为菜单项，不再显示下拉箭头。
  * 效果: 用户在侧边栏只看到一个“员工管理”。点击它进入列表页。在列表页点击“添加”跳转到 /employee/add
    时，侧边栏依然高亮“员工管理”，且不会出现多余的菜单项。
